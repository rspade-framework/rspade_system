## DOCUMENTATION OBLIGATIONS

**THE DOCUMENTATION IS PART OF THE CHANGE.** Man pages (`system/app/RSpade/man/*.txt`, project pages `rsx/resource/man/*.txt`) are the CONTRACT tier and describe what the framework ACTUALLY DOES - a page describing a previous behavior is worse than none, because it is trusted. **Docs move when the CONTRACT or OBSERVABLE BEHAVIOR moves, not when code moves** (a refactor, or a fix that makes the code match what the page always said, needs nothing: "did what a developer can observe, invoke or trip over change?"). When it moved, update the affected tiers - man page, skill, fragment - in the same work **WITHOUT ASKING**; removing a feature removes every passage documenting it. **What still comes to the owner is CHANGING a promise** (narrowing a guarantee, inventing a contract nothing implements, ruling a documented behavior wrong) - propose it, never land it.

**Who a tier serves decides what goes in it**: internal mechanics with no developer-facing seam -> `skills/framework/`, a publish-stripped page or a colocated `Core/*/CLAUDE.md`; anything a developer can observe, invoke or trip over -> a shipped man page + `skills/shared/`. **A downstream developer treats the framework as a black box, and is entitled to**: document internals for them only where they leak into how code is written. Conformance audits (`system/app/RSpade/conformance/`) are a sanctioned channel for contracts no lint rule can enforce, and you may PROPOSE one to the owner.

**MANDATE: a change to the CONTRACT or SYNTAX of how downstream code is written or invoked is not done until every item that applies is done**: (1) monorepo always-on knowledge, terse; (2) the shared fragment, written ONCE; (3) the reference app (`/rsx/`) demonstrating the new way - it SHIPS as `system/app/RSpade/resource/reference_app/`, so never mark a contract change done without it; (4) the man page(s); (5) `breaking_changes/*.txt` ONLY when a downstream developer must CHANGE CODE THEY WROTE (the untouched-fork, black-box and jQuery call-shape tests, plus the likely-overridden-core-model trigger; `IF YOU DO NOTHING:` mandatory; most changes, large ones included, do not qualify); (6) a conformance audit or `launch_checklist` check for a silent change. Skill `rspade:shipping-a-contract-change` (the gate, categories, audit routing).

**References** in prose and comments are spelled `rsx:man topic` / `skill rspade:name` (never `topic(7)`, `topic.txt`) and must resolve; a man page's cross-references sit under `SEE ALSO` (`man/CLAUDE.md`). **External requests**: `docs.dev/external_requests/INDEX.md` is self-maintained (one row per request, updated on every status change) and a FULLY processed request also moves to `archive/` - a file still at the top level is OPEN.
