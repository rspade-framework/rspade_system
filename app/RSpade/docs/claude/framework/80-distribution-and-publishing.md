## DISTRIBUTION & PUBLISHING

**`bin/publish` cuts a production release - NEVER a test step** (skill `rspade:publishing-a-release`). **We AUTHOR the consumer**: downstream, `system/` is a git submodule hard-reset to each release (`reset --hard` + `clean -fdx`), so ALL of `system/` is overwritten and a downstream change lives in `rsx/` (class override). **Durable "make the environment correct" behavior is a script in `system/bin/environment_updates/`** (self-detecting, idempotent, silent; its CLAUDE.md), never an edit to the updater - `framework-pull-upstream.sh.dist` is authoritative and lags one pull (`rsx:man framework_pull_mechanics`). **`rsx/resource/CLAUDE.dist.md` is the starter's CLAUDE.md - a TEMPLATE EXAMPLE of how an end developer uses their own CLAUDE.md, not an index of the app: keep edits to it minimal** (the template's behavior is inferred from conventions and its own comments). `rsx/resource/skills/` ships too.
