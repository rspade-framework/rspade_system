## AUTH GATES

**`#[Auth]` is MANDATORY on every dispatchable surface** — `#[Route]`, `#[SPA]`, `#[Ajax_Endpoint]`, `#[Ajax_Endpoint_Model_Fetch]`, `#[Api_Endpoint]`, `@route` JS actions (never on `#[Companion_Endpoint]`, whose signed request is the gate). **CLOSED BY DEFAULT, with no off switch**: a gateless surface FAILS the manifest build with a per-violation worklist, and a public one declares `#[Auth('public')]`. Built-ins: `public`, `closed`, `is_logged_in`, `is_sysadmin`, `can_impersonate`, `is_framework_developer`. Names are variadic and AND together; a class-level attribute covers every surface in the class and a method-level one only narrows. **`pre_dispatch()` performs NO authorization anywhere** (`@auth-exempt` is dead syntax).

**Gate vs record**: `#[Auth]` answers "may this USER use this surface at all"; a rule whose answer depends on WHICH row is never a gate — it goes in the body (`require_permission()`, `require_role()`). A check is an `#[Auth_Check]` method on the realm's `Permission` class, evaluated LIVE on every ask (keep it cheap); it usually reads **roles** (`users.role_id`, lower id = higher privilege) and **ACLs** (`_user_permissions` GRANT/DENY, DENY wins). **A DEVELOPER is neither** — `login_users.is_developer` (`Session::is_developer()`, `window.rsxapp.is_developer`), set only by hand, never a role. **`can_access($target)`** (PHP and JS) derives link visibility from the destination's own gates. Staff and portal check names are separate realms; a cross-realm name is a build error.

Skills `rspade:auth-gates`, `rspade:permissions-acl`. Details: `rsx:man auth_gates`, `rsx:man acls`.
