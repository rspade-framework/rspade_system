## FILE ATTACHMENTS

`File_Storage_Model` is the content-addressed, deduplicated blob; `File_Attachment_Model` the logical upload with its metadata and owner. The flow is upload-unattached (browser `Ajax.upload(form_data)`, integration `POST /api/v1/files`) -> validate -> claim (`find_by_key()` + `can_user_assign_this_file()` + `attach_to()`/`add_to()`). **An attachment the CALLER named is reached with `$record->find_attachment($id_or_key, $category)`** (null unless it belongs to that record); a file embedded in rich text is claimed with `claim_for_embed()` (category `inline_embed`, left out by `excludingEmbeds()`). **An endpoint filing a NEW upload onto a record asks first when the record already holds those bytes** - `Rsx_Duplicate_Upload::screen()` over `duplicates_on()` (Upload Again / Skip This File / Cancel Upload); the widget calls it through `Rsx_Form.call_answering()`.

**The three file gates are MANDATORY**: with no `file.upload.authorize` / `file.thumbnail.authorize` / `file.download.authorize` handler in `/rsx/handlers/`, uploads and file reads THROW (minimum handler: require login). Framework code asks them only through `Rsx_File_Gates::authorize()`.

**Never build a file URL** - the model's builders (`get_url()` / `get_download_url()` / `get_preview_url()` / `get_thumbnail_url*()`, JS `File_Attachment_Model.inline_url()` / `download_url()` / `thumbnail_url()`) carry a `?v=` content version, and a URL concatenated from the key is served `no-store`. **A thumbnail is `<Attachment_Thumbnail $attachment_id=... />` and nothing else** (ship `file_attachment_id`, never a URL); every preview widget emits `preview_loaded` - never bind `load` on its `<img>`; a file-type mark is `<File_Type_Icon $file_name=...>`. **Never hardcode the size ceiling in a label**: `Ajax::max_file_size_human()` / `Ajax.max_file_size_human()`, and `0` means UNLIMITED. Render and sort a Type column on `file_type_label`, never branch on it. `$attachment->fileable` is the polymorphic parent (never hand-roll an accessor), and `can_view()` / `scope_can_view()` (`Staff_Authorizable`) is the staff read seam, so an app never class-overrides a core model to attach visibility.

**`delete()` is recoverable** (`rsx.files.deleted_retention_days`, `undelete()`); `force_destroy()` is the only erasure and `File_Disposal_Service` the sole blob-release authority. **Output somebody is waiting for (an export, a task's file) is a TEMP FILE** - `Rsx_Temp_Files::store_bytes()` / `store_file()`, served by the feature's own gated endpoint - never an attachment and never `tmp/`. **Every table pointing at a `_file_storage` blob declares `#[Blob_Reference('file_storage_id')]` + `use Blob_Referencing`**, and bytes are read through `read_bytes()` / `read_stream()` / `download_response()`, never a path.

## DOCUMENT RENDERING, SEARCH & PREVIEW

One background worker (`Document_Render_Service`) renders each Office document ONCE to a PDF and extracts its text; a spreadsheet renders in-process to HTML (`Spreadsheet_Viewer`). **So an Office thumbnail, preview and text appear seconds AFTER the upload** (`get_extraction_status()` null while pending), **and writing a render status queues nothing** - use `requeue_render()` / `mark_work_owed()`. **`File_Attachment_Model::search_text($query)` returns a Builder the app MUST site-scope** (`_search_indexes` has no `site_id`). Show a file with `<Document_Preview $attachment_id=... />` / `<Document_Text_Preview>`. **`rsx.documents.stage_seconds` and `kill_seconds` are this subsystem's only sanctioned bounds.**
