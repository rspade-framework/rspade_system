## SESSIONS & LOGIN FLOWS

**Always use `Session`** (static facade) — **never Laravel Auth, never `$_SESSION`.** A session is a BROWSER, holding at most one staff and one portal sign-in. Readers create nothing (`is_logged_in()`, `has_session()`, `get_user()` = this site's membership, `get_login_user()` = the cross-site identity, `get_site_id()`, `is_impersonating()`, `has_api_access()`). **`get_session_id(): ?int` CREATES a guest's session** — "is there one?" is `has_session()` — and is NULL in a command, task and test, so a column storing it is NULLABLE. Browser-scoped state of your own keys on it; **a record of what somebody did stores `Session::get_audit_session_id()`** (skill `rspade:audit-session`).

**Session values** (`put_value()` / `get_value()` / `forget_value()`, realm `'staff'|'portal'|'guest'`) are short-lived, cleared by their realm's sign-out, and never storage; `put_value()` THROWS with no browser. **A preference is a preference variable** (`$user->get_variable()` / `set_variable()`: no expiry, never in a payload), and one every account has for life is a COLUMN.

**Sign-in lifetimes are the framework's** (`rsx.sessions.staff` / `.portal`: `max_length_minutes`, `max_idle_minutes` counted in PAGE VIEWS - a render, an SPA dispatch, a hash change from a person's input, or the app's `Rsx_Session.report_page_view()` from a user action (never a timer, poll or realtime handler) - never Ajax) — **never implement "Remember Me" or a timeout of your own**; limits the APP supplies at run time go through the `session.limits` resolve hook (`Session::get_sign_in_limits()`, the one reader; a bad answer THROWS). The app's one job is the dialog, `Rsx.set_session_expired_handler(fn)`. Sign-in and sign-out ROTATE the session and CSRF tokens.

**A staff login is TWO calls.** `RsxAuth::verify_credentials($credentials)` checks the password AND that the identity holds an enabled site membership, answers the identity or null, signs NOBODY in, and RECORDS the outcome itself (never a `Login_History::record_success()` beside it; `record: false` when a step is still owed, and then you record). `RsxAuth::login($identity)` is the only way into a session — never `Session::set_login_user_id()` — and returns false for an identity with no enabled membership. Whatever the sign-in still owes runs BETWEEN them. `verify_credentials()` THROWS `Auth_Throttled_Exception` ("You're doing that too fast") and `Auth_Password_Reset_Required_Exception`: catch both, never as a wrong password - the throttle's message is the error, and the reset flag starts the FORCED CHANGE (`RsxAuth::begin_forced_password_change($e->identity)` parks it signed out; `complete_forced_password_change($new)` saves through the model and answers the identity STILL NOT signed in, so the second factor and `login()` follow; `Portal_Auth::` twins). **Every password is set with `set_password($plain, Password_Change::CAUSE_*)` + `save()`** - the cause (`self`/`reset_link`/`admin`/`forced_change`/`cli`; none = `unknown`) rides `login_user.password.changed` / `portal_user.password.changed`, fired AFTER COMMIT with `{identity, cause, actor, audit_session_id, ip_address}` - the one hook for auditing or announcing a change; a temporary one adds `require_password_reset()` in the same save (holds over an already-flagged identity). **Account state (`status_id`/`is_activated`/`is_verified`) is APPLICATION vocabulary** — enforce it in your login function AND `Main::pre_dispatch()` (`init()` cannot eject anybody). **`users.is_enabled` and `sites.is_enabled` are the FRAMEWORK's** (`User_Model::is_active()`, `->active()`), enforced at login and on every request — delete your own checks. A step a signed-in user still owes (enrol a factor, accept terms) is APPLICATION code: parked with `put_value()`, redirected to from `Main::pre_dispatch()`. **The site NEVER changes inside a request handler or under a site lock** (the setters THROW: `... refused inside Ajax X::y`); **`RsxAuth::enter_site($site_id)` is the one way a sign-in or site switch moves the browser onto a site**, from a `#[Manual_Lock]` endpoint or a lock-less page route.

**Brute-force throttling (`Login_Throttle`) is ON by default** and refuses before any lookup (`require_not_throttled()`, the first statement of every framework verification). **A failure is counted by RECORDING it, once**: `Login_History::record_failure()` feeds the throttle itself, so never call `Login_Throttle::record_failure()` beside it (that is only for a non-password secret recorded to no history). A box behind a load balancer MUST list it in `TRUSTED_PROXIES`, or every visitor shares one address.

**"Where you're signed in"** is `get_sessions_for_user()` (USER SESSIONS) plus `terminate_session()` / `terminate_all_other_sessions()` / `terminate_*_for_user()`: a guarded REFUSAL THROWS `AjaxUnauthorizedException`, ABSENCE returns false/0 — never conflate them. **A new password saved through the model ends the identity's other sign-ins by itself** — never terminate beside it.

**Built in, never hand-rolled**: CSRF on every internal transport; `Login_Redirect` (`capture()`/`params()`/`consume()`) as the ONE `?redirect=` sanitizer; `Login_Notice` for a sign-in page's sentence (a declared code, no free text in the URL, never a flash); Turnstile — **do NOT install a captcha package**: `<Turnstile_Input />` plus `Rsx_Turnstile::validate($request)` as the FIRST statement of the POST branch ("Turnstile implementation incomplete" = the validate is missing; fix it, never silence it).

**Beyond the password, the framework owns the CEREMONY and the app the endpoints and the POLICY:**
- **`Rsx_Two_Factor`** (TOTP, passkeys, recovery codes, emailed codes): `verify_credentials(..., record: false)` -> `begin_challenge()` -> `verify_challenge()`, which is what signs in; a challenge screen never shows attempts remaining. Skill `rspade:two-factor`.
- **`Rsx_Sso`** (Google, Microsoft, Facebook, Apple, X): a provider is live only because its `enabled` flag is true; the `sso.*` policy hooks FAIL CLOSED; **NEVER match an unverified provider email onto a local account** (account takeover); buttons are `<Sso_Buttons />`. Skill `rspade:sso`.
- **Adding or removing a way into an account** calls `Rsx_Password_Confirmation::require_confirmed()` ("Your password confirmation has timed out. Refresh the page and try again."). Skill `rspade:security-settings`.
- `Rsx_Portal_Two_Factor` / `Rsx_Portal_Sso` are the identical portal APIs.

**The INITIAL USER is `login_users` id 1 AND `users` id 1**, created only by `Rsx_Initial_User::create()`, which fires `user.initial.created` — founder rows go in an `#[OnEvent]` handler, NEVER a migration keyed to user id 1.
