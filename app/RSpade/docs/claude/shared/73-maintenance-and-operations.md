## MAINTENANCE MODE

`php artisan rsx:maintenance:enable --reason="..."` / `rsx:maintenance:disable` take the app down and bring it back (ONE flag file, `storage/state/.maintenance.mode.framework.update`, also raised by `rsx:framework:pull`). Both run PRE-BOOT, so **a flag left stuck by a crash is cleared by simply running disable**, even on a broken tree. **The gate stops AUTOMATION, not humans**: `rsx:task:process`/`rsx:task:worker` are refused and `rsx:task:run` needs `--force` (then queues until the window ends - the task system is off inside it); everything else runs, `migrate` included, against deliberately degraded services (no-op cluster locks, a missing cache, dropped realtime frames; flock system locks untouched). **Disable turns the task system back ON**, even one switched off on purpose beforehand. The web answers 503 + Retry-After while PHP runs, the web server's own 502 once php-fpm is stopped - both mean "down". Skill `rspade:maintenance-mode` (the load-bearing service order, the tolerance list); health rows (`#[Health_Check]`, `Schema Contract`): `rsx:man health`.
