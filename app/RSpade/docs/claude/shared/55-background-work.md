## BACKGROUND WORK (TASKS, LOCKS, SUBPROCESSES)

Background work is a `public static` method on an `Rsx_Service_Abstract` class in `/rsx/services/`, marked `#[Task]`, signature `(Task_Instance $task, array $params = [])`, recurring with `#[Schedule('every 5 minutes')]`. **A MAINTENANCE task (daily or rarer: a purge, a cleanup, a sweep) is `#[Schedule('maintenance')]` + `#[Exclusive('maintenance')]`, never a hard-coded `'daily at 3am'`**, and reports what it changed (`status()`, `progress_count()`, `stdout()`, `summary()`). Every execution is a `_tasks` row (`Task_Run_Model`): `Task::dispatch('Service', 'method', $params)` queues and returns the run id, `Task::internal()` runs in-process and returns the settled row.

**A dispatched run executes as NOBODY - no identity, no site - so a site-scoped READ THROWS** (`Site-scoped read of X_Model with no site declared`; your own `where('site_id', $n)` never overrides it). A task serving ONE tenant declares it with `Session::set_temporary_site_id($site_id)`, cleared in a `finally` (never `set_site_id()`); one whose subject is EVERY tenant reads with `Model::without_site_scope()`, a READ bypass only - a later `save()` of another site's row is REFUSED ("serious security issue"). **The asynchronous stand-in for a user's Ajax endpoint MUST declare `#[Run_As_Dispatcher]`** (it runs bound and frozen as the dispatching sign-in).

**The return value is the RETURN CODE** (`null`/`true`/`0` succeed, `false`/an integer fail): **a task never returns data, and an array is a failed run.** A task reports through `$task` (`status()`, `progress()`, `stdout()`, `summary()`, the queue) and calls `heartbeat()` + `is_stop_requested()` on every loop item: **a worker-run task that reports NOTHING for 30 minutes (`rsx.tasks.silent_timeout`) is killed**, and nothing else limits how long it runs. An attachment (`attach_file()`/`attach_bytes()`) is only for a file the initiator is waiting to take, or a debug artifact; application results go in application tables. `rsx:tasks:disable` / `rsx:tasks:enable` switch the whole system off and on (while off everything queues and inline callers wait).

**A `#[Task]` is a PRIVILEGED SYSTEM CALL, never a web surface.** Ajax and the external API never start one generically: each user-facing operation is its own `#[Auth]`-gated endpoint that validates, runs the ACL and record checks, then calls `Task::dispatch()`; the public API has no task interface, and a site administrator is not a sysadmin. **The browser sees a run only through its task's `#[Task_Access]`** (`'dispatcher'` or a static check; DENY BY DEFAULT - without one, developers only), via `Rsx_Task` and the widgets `<Task_Status_Badge>`, `<Task_Report>`, `<Task_Report_Browser>`, `<Task_Output>`. **An artisan command is a `#[Task]` plus `#[Command('prefix:name', 'Description')]`** - an application writes no command classes.

**KEY: tasks run concurrently and UNGUARDED** - no automatic lock exists, so a task never assumes it is the only writer. `#[Exclusive]` / `#[Debounce(seconds)]` guard ONE task identity against itself and `#[Exclusive('group')]` serializes several tasks; **never take a lock inside the task body for that, and never add a timeout to a task** (one that should yield its worker calls `$task->run_again_in($seconds)`).

**Locks**: `RsxLocks::named_write_lock()` / `named_read_lock()`, `site_write_lock()` / `site_read_lock()`, `system_lock()` (this box only), always released in a `finally` with `RsxLocks::release_lock($token)`. **No lease, no TTL**: held until released or the process dies; `$timeout` is a WAIT budget only.

**MANDATE: spawn `php artisan` ONLY through `Rsx_Artisan`** (`passthru()` / `run()` / `dispatch_detached()`), never `exec`/`shell_exec`/`proc_open` with an artisan line (`ARTISAN-SPAWN-01`): a subprocess is a different lockd connection, so it queues behind locks its PARENT holds while the parent blocks in `waitpid` - a permanent hang the deadlock detector cannot see.

**Scheduling** is one cron line, `* * * * * php artisan rsx:task:process`; inside the RSpade container `rspade-taskd` runs the same tick only when work comes due or the application pokes it (`Task_Daemon::poke()`) - it wakes AT a schedule's time, and a tick claims every schedule due within the next 5 s (`Task_Daemon::SCHEDULE_LEAD_SECONDS`). **A PHP script outside the application boots with `$app = require '<project>/system/script.php';` and nothing else** (`rsx:man scripting`); one that writes many rows calls `Task::spawn_workers(false)` after it.

**A COMPANION APPLICATION** is work that never ends (a watcher, a socket listener, a protocol bridge) under `rsx/companions/<name>/`, run by `rsx-companiond` and calling the app through `#[Companion_Endpoint]` methods (no `#[Auth]`). Traps: the site is declared per request, endpoints must be idempotent, and there is no versioning (`contract_mismatch`).

Skills: `rspade:background-tasks`, `rspade:task-access`, `rspade:task-commands`, `rspade:locks-and-subprocesses`, `rspade:companion-apps`. Details: `rsx:man tasks`, `rsx:man task_commands`, `rsx:man locks`, `rsx:man companion_apps`.
