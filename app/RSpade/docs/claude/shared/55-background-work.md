## BACKGROUND WORK (TASKS, LOCKS, SUBPROCESSES)

Background work is a `public static` method on an `Rsx_Service_Abstract` class in `/rsx/services/`, marked `#[Task]`, signature `(Task_Instance $task, array $params = [])`, recurring with `#[Schedule('every 5 minutes')]`, once per new build with `#[On_Build]` (dispatched by the scheduler tick, never the build; needs `#[Exclusive]`/`#[Debounce]`; first step a cheap "already current?" check - in development it follows every edit). **A MAINTENANCE task (daily or rarer: a purge, a cleanup, a sweep) is `#[Schedule('maintenance')]` + `#[Exclusive('maintenance')]`, never a hard-coded `'daily at 3am'`**, and reports what it changed. Every execution is a `_tasks` row (`Task_Run_Model`): `Task::dispatch('Service', 'method', $params)` queues and returns the run id, `Task::internal()` runs in-process and returns the settled row.

**A dispatched run executes as NOBODY - no identity, no site - so a site-scoped READ THROWS** (`Site-scoped read of X_Model with no site declared`; your own `where('site_id', $n)` never overrides it). A task serving ONE tenant declares it with `Session::set_temporary_site_id($site_id)`, cleared in a `finally` (never `set_site_id()`); one whose subject is EVERY tenant reads with `Model::without_site_scope()`, a READ bypass only - a later `save()` of another site's row is REFUSED ("serious security issue"). **The asynchronous stand-in for a user's Ajax endpoint MUST declare `#[Run_As_Dispatcher]`** (it runs bound and frozen as the dispatching sign-in) - the shape of every export, import, reassignment and mass edit over a variable amount of data.

**The return value is the RETURN CODE** (`null`/`true`/`0` succeed, `false`/an integer fail): **a task never returns data, and an array is a failed run.** A task reports through `$task` and calls `heartbeat()` + `is_stop_requested()` on every loop item: **a worker-run task that reports NOTHING for 30 minutes (`rsx.tasks.silent_timeout`) is killed**, and nothing else limits how long it runs. An attachment (`attach_file()`/`attach_bytes()`) is only for a file the initiator is waiting to take, or a debug artifact; application results go in application tables. `rsx:tasks:disable` / `rsx:tasks:enable` switch the whole system off and on (while off everything queues and inline callers wait).

**A `#[Task]` is a PRIVILEGED SYSTEM CALL, never a web surface.** Ajax and the external API never start one generically: each user-facing operation is its own `#[Auth]`-gated endpoint that validates, runs the ACL and record checks, then calls `Task::dispatch()`; the public API has no task interface, and a site administrator is not a sysadmin. **The browser sees a run only through its task's `#[Task_Access]`** (DENY BY DEFAULT - without one, developers only; skill `rspade:task-access`). **An artisan command is a `#[Task]` plus `#[Command('prefix:name', 'Description')]`** - an application writes no command classes.

**KEY: a task takes NO automatic lock or transaction, but is ENFORCED** - a site-scoped `save()`/`delete()` fatals (`Site lock enforcement: ... by task X::y`) unless it runs in **`Site_Lock::write($site_id, fn () => ...)`, ONE SECTION PER ITEM that RE-READS the record inside**, or a reasoned `Site_Lock::bypass()` / `bypass_all_sites()` for a pass that tolerates concurrent writers; change site only between sections. **Every artisan command and `system/script.php` script likewise** - only provisioning commands carry `const SITE_LOCK_EXEMPT = '<reason>'`. `#[Exclusive]` / `#[Debounce(seconds)]` guard ONE task identity against itself and `#[Exclusive('group')]` serializes several tasks; **never take a lock inside the task body for that, and never add a timeout to a task** (one that should yield its worker calls `$task->run_again_in($seconds)`). Skill `rspade:site-locks`.

**Locks**: `Site_Lock::write()` / `read()` for a site's data; `RsxLocks::named_write_lock()` / `named_read_lock()` for other shared state, `system_lock()` (this box only), released in a `finally` with `RsxLocks::release_lock($token)`. **No lease, no TTL**: held until released or the process dies; `$timeout` is a WAIT budget only.

**MANDATE: spawn `php artisan` ONLY through `Rsx_Artisan`** (`passthru()` / `run()` / `dispatch_detached()`), never `exec`/`shell_exec`/`proc_open` with an artisan line (`ARTISAN-SPAWN-01`): a subprocess is a different lockd connection, so it queues behind locks its PARENT holds while the parent blocks in `waitpid` - a permanent hang the deadlock detector cannot see.

**Scheduling** is one cron line, `* * * * * php artisan rsx:task:process` (in the container `rspade-taskd` runs it when work comes due). **A PHP script outside the application boots with `$app = require '<project>/system/script.php';` and nothing else** (`rsx:man scripting`); one that writes many rows calls `Task::spawn_workers(false)` after it.

**A COMPANION APPLICATION** is work that never ends (a watcher, a socket listener, a protocol bridge) under `rsx/companions/<name>/`, run by `rsx-companiond`, calling the app through idempotent `#[Companion_Endpoint]` methods (no `#[Auth]`; readers unless `#[Writer]`; no versioning - `contract_mismatch`).

Skills: `rspade:site-locks`, `rspade:background-tasks`, `rspade:task-access`, `rspade:task-commands`, `rspade:locks-and-subprocesses`, `rspade:companion-apps`. Details: `rsx:man tasks`, `rsx:man site_locks`, `rsx:man task_commands`, `rsx:man locks`, `rsx:man companion_apps`.
