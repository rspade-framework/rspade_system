## PATHS, CONFIG & ENVIRONMENT

**Laravel runs FROM `system/`: `base_path()` is `<project>/system`, never the project root** - `base_path('storage/...')` lands inside the framework tree, where nothing lives. **Three volatile trees sit beside it, owned by `App\RSpade\Core\Paths\Rsx_Project_Paths` alone**: `build/` (what `rsx:build` produces; fixed in place), `tmp/` (derived caches and scratch - and **Laravel's storage path, so `storage_path()` is DISPOSABLE**: durable files go on a `Storage` disk or `Rsx_Project_Paths::app_dir()`), `storage/` (uploads, logs, `storage/state`; the tree to back up). `tmp/` and `storage/` are relocatable (`RSX_TMP_PATH`/`RSX_STORAGE_PATH`), so **never write one of these paths as a literal** - `build_path()`/`tmp_path()`/`storage_path()`/`state_path()` and the named methods (`bundles_dir()`, `logs_dir()`, `flock_dir()`, ...) are the API, and `PATH-OWNER-01` flags a literal. A `./`-relative string addresses nothing a subprocess can rely on; reach a resource file with `__DIR__` or `base_path('rsx/...')`.

**Layout**: `rsx/` is your code (`app/`, `models/`, `lib/`, `services/`, `companions/`, `handlers/`, `theme/`, `resource/`, `public/`); `system/` is the framework. **Any directory named `resource/` or `public/` is ignored by the manifest** (`public/` is web-served; `rsx/resource/config/` is the one exception), and **classes are found by NAME, not path** - no imports, no manual namespaces.

**Config**: framework `system/config/rsx.php` (**never modify**) deep-merged with `rsx/resource/config/rsx.php`; a Laravel config file is overridden by a same-named file there. **`env()` ONLY for deployment-specific values** (`DB_PASSWORD`, `REDIS_HOST`); behaviour belongs in config, under version control. **`system/app/Http/Kernel.php` is framework-owned** - app middleware is declared in `config('rsx.middleware.global')` (append-only, runs after the framework stack; there is no Laravel router, so no route middleware).

**`APP_URL` is the single hostname source** (`Rsx::get_hostname()`, `is_dev_site()` = contains `.dev.`, mailed links through `rsx_absolute_url()`); **outside development it must be https or boot throws**, and a browsed host that disagrees fatals loudly. **There is no hostname-derived "debug site"**: credential auto-fill is the boolean `RSPADE_LOGIN_AUTOFILL`, off unless a developer turned it on.

**`.env` is local and never distributed; the tracked project-root `.env.dist` holds the canonical defaults, and its KEYS propagate into `.env` on every development boot (values never).** So **to remove a setting set it EMPTY** - a deleted line comes back - and **every NEW key goes in `.env.dist`** with a default or an empty string, never a secret. A `.env` edit that silently did nothing is `system/.env` symlink drift: `rsx:env:heal`.

Skill `rspade:environment-config` (merge semantics, APP_URL/PORTAL_URL on a new host and the `$HOSTNAME` spelling, the hostname-guard fatal, `.env` drift, an encrypted `.env`, which path helper). Details: `rsx:man config_rsx`, `rsx:man storage_directories`.
