## APPLICATION MODES & SEALED BUILDS

Three modes - `development`, `debug`, `production` - switched with `php artisan rsx:mode:set dev|debug|prod` (lifecycle: `rsx:prod:enable [--debug]` / `rsx:prod:disable` / `rsx:prod:verify`). **`RSX_MODE` in `.env` is the ONLY mode source and you never edit it by hand**: Laravel's `app.env`/`app.debug` derive from it and `APP_ENV`/`APP_DEBUG` are read nowhere. **Per-invocation intent is a `--flag`, never a `KEY=VALUE` env prefix** (owner ruling).

**A DEV BOX IS AS IMPORTANT AS A PROD BOX, AND SECURITY IS PLANNED FOR DEVELOPMENT MODE (owner rulings).** A development-mode site may be serving the public, as production, right now: a feature that "only breaks in dev" is broken, a mode-conditional weakening of a security control is a defect, every developer convenience that crosses the wire (dev-auth headers, the IDE bridge, error dumps) is designed against an attacker who has read the source, the question is `Rsx::is_development()` against a threat model and never "not production", and "only reachable in development" is never a mitigation. A sealed build differs ONLY by skipping env checks and source rebuilds, minifying (strict production also obfuscates app strings - `_$$SC`/`_$$`/`_$$R` are reserved globals - and strips `console.log`), the component shake (a component reached only by a name assembled at run time goes in the bundle's `'keep'` list) and suppressing diagnostic dumps.

**`debug` and `production` are SEALED - built once by `rsx:build`, then immutable**: editing a file changes nothing served, and after pulling code onto a sealed host you run `rsx:build --force` or nothing changes. Unsealed, a prod box refuses everything but the build and the mode transitions (`This production build is unsealed. Run: php artisan rsx:build --force.`); `rsx:prod:verify` detects drift. **External assets are mirrored into `rsx/resource/.cdn-cache/` in EVERY mode - no development exception - and that store is git-tracked source: commit what a compile adds** (`rsx:cdn_externals:refresh` is its one expiry). **In development, `artisan` refuses to run outside the RSpade container** (`/.rspade_container`; the refusal prints the `docker compose exec` line). **Before launch, BOTH `rsx:man launch_checklist` AND the launch conformance audits (`rsx:conformance:list --when=launch`)** - neither replaces the other.

Skill `rspade:application-modes-deployment` (refusal catalog, the seal, the build/tmp/storage read-only posture, state key vs build key, the container gate, deploy recipe). Details: `rsx:man prod`, `rsx:man app_mode`.
