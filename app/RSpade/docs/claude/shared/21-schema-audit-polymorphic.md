## SCHEMA, AUDIT AUTHORSHIP & POLYMORPHIC REFERENCES

**Migrations are forward-only, raw SQL through `DB::statement()`** (Schema builder prohibited), created with `make:migration:safe`. **No defensive coding** - no `IF EXISTS`, no `information_schema`: know the state, write the exact transformation. **A migration never writes through a model** (model writes THROW "refused: a migration is executing" while `up()` runs) - SQL only; a change to what a derived column reads ends with `Rsx_Rederive::enqueue('table')`, rederived as `migrate`'s last step. **Run `migrate` freely, and ALWAYS with its FULL output** - never `| tail`/`| head`/grep; the snapshot/rollback narrative is the diagnostic. **Never regenerate the shipped schema cache on your own initiative** - a stale cache is never a bug, and `rsx:db:rebuild_provision_cache_snapshot` is operator-requested. Production protection (`--dump-rollback`), cancelled runs, the fresh-database cache restore: skill `rspade:migrations`.

**A `_`-prefixed TABLE is private to the framework, schema included** - `rsx/` code never queries, joins or depends on one (`DB::table('_sessions')`); reach it through the published interface (`Session::get_sessions_for_user()`, `Login_History`, `$record->revisions()`, ...), and when none fits, **submit a change request to RSpade** - its columns are not a contract. The two sanctioned contacts: a `FOREIGN KEY ... REFERENCES _sessions (id) ON DELETE CASCADE`, and joins a framework call makes (`Audit_Session::join()`). **A `_`-prefixed COLUMN is a system column the same way** - stripped from every payload, from JS `field_length()` and from revision diffs (`__MODEL`/`__details` excepted) - so a framework feature's per-record state on an app table is named `_foo`, and an app-facing column never takes a leading underscore. `rsx:man database_schema_architecture`.

**Audit authorship**: every table carries `created_by_id`+`created_by_type` (and `updated_by_*`, `deleted_by_*`) pairs, stamped by `save()` automatically; an explicitly set pair wins and is set as ONE unit. **Migrations never declare audit columns** and never reference them positionally (`AFTER updated_by`). **An actor model extends `Rsx_Actor_Model_Abstract` / `Rsx_Site_Actor_Model_Abstract` and is never hard-deleted** (`ACTOR-01`, build FATAL). Skill `rspade:actors-and-authorship`.

**A polymorphic reference is ALWAYS the BIGINT pair `{relation}_type` + `{relation}_id`**, the `_type` column declared `['type_ref' => true]` in `$columns` (**never a VARCHAR class name**, never two parallel nullable FKs; `class_basename()`, never `get_class()`); `POLY-01` is a build FATAL. Skill `rspade:polymorphic`.
