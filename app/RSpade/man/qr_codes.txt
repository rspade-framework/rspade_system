NAME
       qr_codes - generating a QR code as an inline SVG

SYNOPSIS
       PHP:
           use App\RSpade\Core\Qr\Rsx_Qr_Code;

           $qr = Rsx_Qr_Code::generate($text);

           $qr['svg']       // string - the inline <svg> element
           $qr['size_px']   // int    - recommended side length on screen, CSS pixels
           $qr['size_in']   // float  - recommended side length on paper, inches
           $qr['modules']   // int    - modules per side, quiet zone included

DESCRIPTION
       Rsx_Qr_Code::generate() is the one way to make a QR code. It is called on
       the server, by whatever builds the page's data, and its result is plain
       data that travels in a view's variables or an Ajax payload like any other.

       There is nothing to configure. Every code is made the same way:

           error correction   level Q - the code still reads with about a quarter
                              of it damaged, which is what a printed sheet that is
                              folded, smudged or photocopied needs.
           colours            black on an opaque white ground, always. A dark
                              theme does not reach it.
           quiet zone         the four-module white margin the specification
                              requires, INSIDE the image. Nothing has to be left
                              clear around the element.
           format             vector. One SVG is sharp on every screen and at every
                              printer resolution. There is no PNG and no <img> form.

       There is no URL that serves a QR code and no endpoint that encodes text on
       request: a code is generated where its content is already known.

SIZE
       A code holding more text has more modules and needs more room, so the
       recommended sizes are computed for each code rather than fixed:

           size_px   4 CSS pixels per module. A short URL is about 150.
           size_in   0.02 inch (half a millimetre) per module, never less than
                     1.0. A short URL is 1.0.

       The SVG carries size_px as its own width and height, so placed on a page
       untouched it is already the recommended screen size. CSS on the element
       overrides that; a code is square, so one number is the whole size.

       These are recommendations for a code scanned at arm's length. Larger is
       always safe. Smaller than size_in on paper is where scanning starts to
       fail.

USAGE
       In a jqhtml template the SVG is interpolated RAW - it is markup, and every
       character of it is generated by the framework (none comes from the text):

           <div class="My_Sheet__qr"><%!= this.data.qr.svg %></div>

       In Blade: {!! $qr['svg'] !!}

       On a sheet meant for paper, size the element in inches from size_in:

           <div class="My_Sheet__qr" style="width: <%= this.data.qr.size_in %>in">
               <%!= this.data.qr.svg %>
           </div>

           .My_Sheet {
               &__qr svg { display: block; width: 100%; height: auto; }
           }

       Browsers honour physical units when printing, so that element prints at
       the stated size.

LIMITS
       $text is normally a URL. An empty string throws InvalidArgumentException.
       Text longer than a QR code can hold at level Q (about 1,600 characters)
       throws from the encoder. Encode a short URL that leads to the content
       rather than the content itself: every extra character makes the code
       denser and the recommended size larger.

       An email cannot carry one. Mail clients strip inline SVG; link to a page
       that shows the code instead.

       The QR library itself (bacon/bacon-qr-code) is a framework-internal
       dependency and is not exposed to application code. Rsx_Qr_Code is the
       interface.
