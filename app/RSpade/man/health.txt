NAME
    health - rsx:health environment/dependency verification and the
    #[Health_Check] attribute

SYNOPSIS
    php artisan rsx:health
    php artisan rsx:health --json

    Declare a check WHERE its feature lives:

        #[Health_Check('Human Label')]
        public static function my_probe(): array
        {
            return ['status' => 'OK', 'detail' => '...'];
        }

    Declare which modes it applies to (absent = every mode):

        #[Health_Check('Playwright / Chromium', modes: 'development')]
        #[Health_Check('Production Seal', modes: ['debug', 'production'])]

DESCRIPTION
    rsx:health verifies that every dependency, service, and environment invariant
    RSpade relies on is installed, reachable, and sane, and reports OK / WARN / FAIL /
    INFO per check with a remediation hint. The motivating scenario: a client, CI job,
    or fresh container stands up a copy of the site and needs ONE command that says
    "this environment can actually run everything" before failures surface deep inside
    a feature.

    The inventory is not hardcoded. Each check is DECLARED WHERE ITS FEATURE LIVES via
    a bare #[Health_Check('label')] attribute on a public static method, discovered
    through the manifest by Health_Check_Runner. A feature that needs soffice registers
    its own soffice probe, so the health inventory can never drift from the features it
    covers - and an app declares its OWN checks the same way (that is the point).

    Unlike a Laravel health package with a central registry you keep in sync, RSX finds
    checks by manifest attribute scan - no registration, no service provider.

COMMAND BEHAVIOR
    Default: a Check / Status / Detail / Remediation table (house style mirrors
    rsx:prod:verify), ASCII only, ending in a [OK] or [FAIL] bracket summary.

    --json: a machine-readable payload only:
        {"generated_at": ..., "mode": "development", "ok": bool,
         "skipped": ["label", ...],
         "checks": [{label, status, detail, remediation}]}

    Both forms report the MODE they ran in and the labels of the checks that do
    not apply to it: a footer line under the table ("Mode: production" /
    "Not applicable in this mode: ..."), the "mode" and "skipped" fields in the
    JSON. A row an operator expected and did not get is therefore explained on
    the same screen.

    Exit code: 1 if and only if at least one FAIL row exists. WARN and INFO NEVER flip
    the exit code - they are advisory - so a deploy pipeline or container healthcheck
    can gate on rsx:health while tolerating warnings (e.g. a not-yet-running cron).

    The command is safe on a live site: checks are read-only probes (no destructive
    tests). A check that throws or returns an out-of-contract shape becomes a single
    FAIL row naming the offender - one broken check never aborts the rest of the report.

THE #[Health_Check] ATTRIBUTE
    - Placed on a PUBLIC STATIC method taking no arguments.
    - Requires a label: #[Health_Check('Human Label')] (a bare marker attribute -
      NEVER a defined class; reflection metadata only, like #[Route]/#[Task]).
    - The method must live in a manifest-scanned directory (framework /system or app
      /rsx) so the attribute scan finds it. Declare it in the FEATURE that owns the
      dependency, not in a central file.
    - A missing label fails loud at discovery.
    - modes: names the application modes the check applies to - a bare string or
      a list, drawn from development | debug | production. ABSENT MEANS EVERY
      MODE, which is the right answer for most checks. An unknown name fails
      loud at discovery, exactly as a missing label does: a typo would otherwise
      silence the check on every box, which is the one outcome nobody notices.
      LITERALS ONLY - attribute arguments are read by reflection before the
      autoloader is ready, so a class constant there dies at the scan.

    THE MODE AXIS. A check whose modes exclude the running RSX_MODE is NOT
    INVOKED and produces no row. The reason is signal: a development tool
    reported as missing on a production box is an absence that box is correct to
    have, and a row nobody acts on devalues every row beside it. The converse
    matters more - a sealed box has questions development cannot answer (is the
    seal intact, is a development convenience still switched on), and before the
    axis existed there was nowhere to ask them.

    Two rules follow for an app declaring its own checks:

      - Declare modes only when the check would report a WRONG answer in the
        modes you exclude. "Slow" or "noisy" is not a reason; nothing is skipped
        for cost.
      - A check that BRANCHES on the mode internally (reporting a different
        status or detail per mode) declares no modes at all. Those are different
        questions with different answers, not one question that does not apply.

    Return contract - a single row OR a list of rows:

        ['status'      => 'OK' | 'WARN' | 'FAIL' | 'INFO',   // required
         'detail'      => string,                            // what was found
         'remediation' => ?string,                           // how to fix (optional)
         'label'       => ?string]                           // per-row label override

    A single method may return a LIST of rows to report several sub-checks (e.g. PHP
    version + each extension). With no per-row 'label', later rows inherit the
    attribute label suffixed #2, #3, ...

    Status meanings:
        OK     working.
        WARN   advisory - degraded or unverifiable, but not a hard stop (does not fail
               the exit code).
        FAIL   broken - the environment cannot run the feature (fails the exit code).
        INFO   informational posture, not a pass/fail (e.g. the active RSX mode, or a
               feature intentionally disabled by config).

    Example (a feature declaring its own dependency probe):

        #[Health_Check('LibreOffice (soffice)')]
        public static function soffice_available(): array
        {
            if (config('rsx.libreoffice.enabled', true) === false) {
                return ['status' => 'INFO', 'detail' => 'disabled by config'];
            }
            $binary = static::find_soffice();
            if ($binary === null) {
                return [
                    'status' => 'FAIL',
                    'detail' => 'soffice not found',
                    'remediation' => 'apt-get install -y --no-install-recommends libreoffice',
                ];
            }
            return ['status' => 'OK', 'detail' => 'soffice at ' . $binary];
        }

    What each one reports:

        APP_URL Scheme           the CONFIGURED application URL is https. FAIL
                                 otherwise. Rsx_App_Url throws at boot on a
                                 non-https APP_URL outside development, reading
                                 the RAW environment; this row reads the value the
                                 application is actually running with, which on a
                                 sealed box comes from the cached config the build
                                 produced - so it catches the one shape the guard
                                 cannot see, a .env repaired after the build. The
                                 remediation says so: edit .env, then rsx:build
                                 --force.
        Application Mode         active RSX_MODE, plus - in a production mode only -
                                 an INFO row per deployed tree (system/, rsx/,
                                 build/) stating whether the current process can
                                 write it (the recommended posture is read-only; see
                                 rsx:man prod), and a WARN when the default log
                                 channel resolves to level debug (remediation:
                                 LOG_LEVEL=info in .env). A stack channel resolves
                                 to the LOUDEST level any of its members accepts.
        Claude Skills            every rsx/resource/skills/<name>/SKILL.md is linked
                                 into .claude/skills/. WARN per unlinked skill,
                                 framework-created dangling link, or blocked/reserved
                                 name; OK with a count otherwise. Remediation:
                                 rsx:heal claude-skills. See template_app(3).
        Document Render Backlog  render + extraction queue depth and failed
                                 counts (pending/failed/unindexed/extract_failed).
                                 ONE probe for one worker and one queue; it
                                 replaced "Search Index Backlog" on 2026-08-22.
                                 Remediation points at rsx:documents:status.
        Console Debug            INFO naming the sealed variant: strict
                                 production strips every console_debug() call
                                 site from the bundle and returns early in the
                                 PHP gate whatever CONSOLE_DEBUG_ENABLED says;
                                 the debug variant keeps both, which is the
                                 point of the variant. Neither is wrong, so it
                                 never WARNs - it is the one-line answer to "why
                                 is there debug output in this browser".
        Env Symlink              system/.env symlink to root .env intact
        Hostname                 the host of the CONFIGURED application URL does not
                                 contain '.dev.'. FAIL when it does: that substring is
                                 what Rsx::is_dev_site() reads, and two outbound
                                 channels gate on the answer - with live delivery every
                                 email recipient is checked against the dev-site
                                 whitelists and otherwise rewritten to the catchall,
                                 and an SMS is gated whatever the delivery mode is and
                                 recorded Suppressed when nothing matches. So a
                                 production site on a .dev. hostname silently stops
                                 writing to its own users: the queue drains, the rows
                                 read Sent or Suppressed, and nobody is told.
                                 Remediation: set APP_URL to the production hostname,
                                 then rsx:build --force.
        LibreOffice (soffice)    headless soffice present (or disabled)
        Lock Server              rsx-lockd listening (INFO under maintenance)
        Mail delivery            which of the four modes rsx.mail.delivery is

                                 disabled.
        Mail sender domain       SPF + DMARC (+ DKIM when rsx.mail.dkim_selector is
                                 set) published for the From domain. WARN when
                                 missing - the fix is a registrar DNS change; INFO
                                 for an example.* sender or any mode but 'live'.
        Mail transport           TCP connect to the transport's host:port (or the
                                 sendmail binary), plus - in aiosmtpd mode - a check
                                 that the SMTP greeting says 'aiosmtpd'. FAIL when it

        Login Auto-fill          RSPADE_LOGIN_AUTOFILL is off. FAIL when it is

        Pending Migrations       schema up to date
        Playwright / Chromium    node, the Playwright package and the Chromium

                                 three install commands are Playwright_Stack,

        Redis Connectivity       Redis reachable (cache, realtime, task slots)

                                 application-owned (non-underscore) tables is still
                                 there. One row per contracted table (`schema: users`,
                                 `schema: login_users`, ...) plus `schema: foreign
                                 keys`, `schema: rows` and `schema: semantics`. FAIL on
                                 a missing table, required column, unique index,
                                 foreign key or required row, with the finding naming
                                 the column or index AND the framework code that reads
                                 it, so an operator can see it is the framework and not
                                 their own feature that is about to fail. WARN for a
                                 semantic probe - present and silently wrong (a NULL
                                 user_permissions.is_grant is a permission lost, a NULL
                                 users.is_api_access_enabled is an API opened). The
                                 declaration is Core/Database/Schema_Contract; audit

                                 migrate:normalize_schema guarantees them, and
                                 deleted_at is included because it does not. This is
                                 the only check that reads the framework's assumptions

                                 rsx:man database_schema_architecture.

                                 write: storage/ (user data) and tmp/ (derived
                                 caches) in every mode, build/ in development only -
                                 a production mode writes build/ once, from
                                 rsx:build, and only reads it afterwards. All three
                                 are EXIST-OR-CREATE: a missing one is created here
                                 rather than reported, and only absent-and-
                                 uncreatable or present-and-unwritable is a FAIL.
                                 Feature subdirs (storage/logs, tmp/thumbnails,
                                 tmp/renditions) are created on first use, so a
                                 missing one is a WARN.

                                 Three more rows come with the split. `tmp/logs
                                 link` and `tmp/app link` check the two symlinks
                                 inside tmp/ that send storage_path('logs') and
                                 storage_path('app') back into persistent storage -
                                 FAIL when one is missing, points elsewhere, or has
                                 been replaced by real content, because a broken one
                                 is a silent data-loss shape rather than an error.
                                 `PHP temp dir` reports where sys_get_temp_dir()
                                 resolves: OK under the tmp root, WARN otherwise,
                                 naming TMPDIR (a php-fpm pool, an ini or a
                                 supervisor program answered first, and third-party
                                 scratch is landing outside the project).
        Task Scheduler Liveness  rsx:task:process cron ticking, inferred from
                                 #[Schedule] tracker staleness. WARN in
                                 development, where a box that is not left
                                 running is expected to have a stale tracker;
                                 FAIL on a sealed build, where nothing would be
                                 sweeping the mail queue, rendering documents,
                                 rotating logs or reaping workers and every one
                                 of those failures is silent. The signal cannot
                                 say WHICH of a dead cron and a wedged pool is
                                 wrong, and says so.
        Turnstile                INFO when disabled; FAIL when enabled with a
                                 missing key (half-configured install)
        Web Exposure             sensitive files are NOT web-served (see below)
        poppler-utils (pdftotext) PDF text-extraction binary present

    An app's own #[Health_Check] methods appear in the same table, ordered by label.

    THERE IS DELIBERATELY NO OPcache ROW. Whether a host runs OPcache is the host's
    decision - a php.ini setting on a machine this framework does not own - and
    rsx:health runs under the CLI SAPI, where the php-fpm values are not visible
    anyway. The framework reminds instead of checking: a web process with no OPcache
    writes ONE log warning naming opcache.enable=1, at most once every six hours per
    build key (Opcache_Advisory, called at the end of Rsx_Framework_Provider::boot()).
    See rsx:man prod, ADMINISTRATION.

PHP EXTENSION CONTRACT
    ONE DECLARATION. App\RSpade\Core\Health\Rsx_Php_Requirements holds
    REQUIRED_EXTENSIONS, REQUIRED_CLI_EXTENSIONS and MIN_PHP_VERSION, and nothing
    else declares any of them. Two consumers read it:

        Environment_Health_Checks::php_environment()   the DIAGNOSTIC - one OK
            summary row per tier ("PHP Extensions", "PHP CLI Extensions") listing
            what is loaded, plus one FAIL row per missing extension carrying its
            own remediation.

        Rsx_Php_Requirements::enforce()                the GUARD - the first
            statement of Rsx_Framework_Provider::boot(). Runs on EVERY web request
            and EVERY artisan invocation.

    TWO TIERS.

        REQUIRED_EXTENSIONS      the RUNTIME tier - every SAPI, always.
        REQUIRED_CLI_EXTENSIONS  the CLI tier - enforced only when PHP_SAPI is
                                 'cli'. Today: pcntl.

    enforce() reads PHP_SAPI and delegates to enforce_for_sapi(); extensions_for_sapi()
    is the composition, and both take the SAPI as a parameter so a caller can ask
    what the check would do elsewhere without pretending to be there.

    WHY pcntl IS CLI-ONLY. Debian/sury compile it into php-cli and not into
    php-fpm, because pcntl_fork() in an fpm worker duplicates the pool's sockets
    and database connections and corrupts them. That is correct packaging, not an
    omission to work around - so a flat single list would have to either refuse
    every web request or leave the CLI code that uses pcntl unguaranteed. The tier
    split refuses neither. Db_Rebuild_Provision_Cache_Snapshot_Command's SIGINT/SIGTERM handlers
    therefore call pcntl_async_signals() unconditionally: the boot check has
    already guaranteed it by the time any command runs.

    THE BOOT CHECK. extension_loaded() over the list; microseconds. On any missing
    extension it THROWS, naming every missing one. There is no degraded mode: the
    framework has no fallback path for a missing extension anywhere (no
    GD-instead-of-Imagick, no file-cache-instead-of-Redis), so an environment
    missing one is misconfigured and says so at the entrypoint rather than three
    layers into whichever feature touches it first.

    Placement is deliberate and was measured: Rsx_Framework_Provider::boot() is the
    earliest point shared by the web entrypoint and artisan at which a throw renders
    READABLY, and it precedes every framework subsystem (manifest, autoloader, Main
    init), so nothing gets a chance to fail in its own idiom first. Raised any
    earlier - from Rsx_Preboot_Service::init() / AppServiceProvider::register() - the
    web response is a blank fatal instead of an error page. It sits beside the
    deferred APP_URL scheme enforcement, which is here for the same reason (see
    bootstrap/app.php).

    THE EXEMPTION. rsx:health and rsx:heal - and nothing else - run with the check
    stood down. They are how a missing extension is diagnosed and repaired, and a
    guard standing between the operator and the lever that fixes the thing it is
    complaining about is a deadlock, not a guard. The exemption is CLI-only and
    reads argv[1], the same shape system/artisan's pre-boot maintenance
    interception uses. A web request is never exempt.

    REMEDIATION, TWO BRANCHES. When /.rspade_container is present (the marker the
    framework's own Dockerfile writes) the remediation says the RSpade development
    container image may need to be REGENERATED to install the additional
    dependency, and names both the versioned apt package (php<major>.<minor>-<ext>)
    and system/app/RSpade/resource/docker/Dockerfile. Outside the container it is
    the ordinary "install/enable the php-<ext> extension". The boot throw carries
    the same two branches.

    ADDING AN EXTENSION is a promise about every environment this framework runs
    in. It ships with the apt package added to that Dockerfile and a note here.
    The framework image installs php-zstd as of 2026-08-28: zstd is declared ahead
    of its first call site because the revision-history feature is built on it, so
    a box without it fails at boot rather than at the first revision write.

    TWO DECLARED EXTENSIONS HAVE NO DOCKERFILE LINE, and must never be given one:
    sodium is compiled into sury's PHP binary and publishes no package (naming one
    fails the image build the same way php-opcache does), and pcntl arrives inside
    php<version>-cli.

    ldap, imap and sodium are declared as the RSpade STANDARD LIBRARY rather than
    from a framework call site - a downstream app is told it may reach for
    directory authentication, mailbox reading and libsodium without first asking
    what the box has. See `rsx:man standard_library`.

    WHAT IS NOT DECLARED. An extension is declared because framework code calls
    it or because it is part of the standard library promised to applications
    (intl, bcmath, soap are the latter). exif, calendar, mysqli and sockets are
    installed by the image but promised by nothing, so they are absent from the
    list on purpose.

WEB EXPOSURE CHECK
    Security_Health_Checks::web_exposure() actively PROVES that sensitive files
    outside system/public are not reachable over HTTP, rather than trusting the
    docroot config. It fetches each target from the site's OWN APP_URL and
    CONTENT-MATCHES the response against the real on-disk file (not just the status
    code - an SPA/catch-all that answers 200 with index.html for unknown paths
    would false-positive a status-only probe).

    Probed targets (one row each):
        .env             the project-root .env (matched on its APP_KEY / first
                         KEY=VALUE line)
        .git/HEAD        the repo's dumpability canary
        .git/config      leaks remote URLs (matched on repositoryformatversion)
        IDE bridge dir   storage/rsx-ide-bridge/ - writes a random throwaway
                         marker, GETs it via the candidate misconfig URLs, then
                         deletes it

    Row outcomes:
        FAIL  the file's real content is served over HTTP -> misconfigured docroot
              / autoindex. A FAIL flips the exit code to 1.
        WARN  the site's own APP_URL is unreachable (never a false OK).
        OK    not web-served, or the file is absent on disk.

    Remediation for a FAIL: point the web-server docroot at system/public ONLY and
    deny dotfiles/.git/.env. This defense does not rely on file permissions (a
    stray chmod cannot defeat it).

RSX VS LARAVEL
    Laravel: a health package with a central config listing checks you maintain.
    RSX:     #[Health_Check] on a static method, manifest-discovered where the feature
             lives; the inventory cannot drift from the code.
