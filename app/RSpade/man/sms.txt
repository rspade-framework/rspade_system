NAME
    sms - Queue-based SMS with dev-site safety and opt-out management

SYNOPSIS
    use App\RSpade\Core\Sms\Rsx_Sms;

    Rsx_Sms::send('+15555550123', 'Your code is 4821', Rsx_Sms::TRANSACTIONAL);

    Rsx_Sms::block_all('+15555550123');            // block all non-transactional
    Rsx_Sms::block('+1555...', Rsx_Sms::MARKETING);
    Rsx_Sms::is_blocked('+1555...', Rsx_Sms::MARKETING);

DESCRIPTION
    The SMS system is the deliberate mirror of the email system (see email(7)): a
    one-call facade that QUEUES every message to sms_queue - never sends inline -
    plus a background drain with the same claim, the same statuses, the same
    retention and the same dev-site gating. It is framework core.

    NO SMS PROVIDER IS WIRED. config('rsx.sms.delivery') is 'suppressed' and there
    is nothing to hand a message to, so the drain records every claimed row
    SUPPRESSED with the reason "no SMS provider configured". That is the current
    behaviour, not a defect: a message nobody can deliver is not pending, it is not
    going, and the row says so. The body is stored verbatim, so an app can show an
    SMS log.

DELIVERY MODES
    config('rsx.sms.delivery') mirrors the mail switch's VOCABULARY, minus the two
    values that need a transport. Anything else THROWS (Rsx_Sms::delivery_mode()):

        suppressed   THE DEFAULT. Every claimed row is recorded SUPPRESSED.
        disabled     THE QUEUE IS FROZEN. send() still queues; the drain logs one
                     line ("SMS delivery is disabled - N message(s) left pending")
                     and returns. Rows stay Pending, untouched.

        live         REFUSED, out loud. There is no provider to be live against, and
        aiosmtpd     accepting the word would mean quietly doing nothing.

    THERE IS NO rsx.sms.stale_after_days, and there must not be. The mail side's
    stale-message window (email(7), THE STALE-MESSAGE WINDOW) is queue hygiene: it
    stops a queue that silently broke for a month from flooding a month of stale
    notices the moment somebody repairs it. An SMS queue cannot accumulate that
    backlog - there is no provider to break, and every row is recorded SUPPRESSED on
    its first pass. When a provider is wired, adding the mirror is the moment to
    revisit this - not before.

    The drain's loop SHAPE is the mail runner's (claim_next -> attempt -> terminal
    status), so wiring a provider means replacing the body of the try and adding the
    two catches, not designing a queue.

    Unlike email there is no class, no template, no subject and no rendered HTML -
    `body` is the content.

    Models (framework core, overridable via the class-override pattern):
        App\RSpade\Core\Models\Sms_Queue_Model      the queue
        App\RSpade\Core\Models\Sms_Recipient_Model  per-number blocklist + stats

SENDING
    Rsx_Sms::send($to, $body, $category = NOTIFICATION, $related_type = null,
                  $related_id = null): Sms_Queue_Model

        $to           destination number (E.164 recommended, e.g. +15555550123)
        $body         message text
        $category     TRANSACTIONAL | NOTIFICATION | MARKETING
        $related_*    optional polymorphic reference to what triggered the SMS

    send() resolves the site from the EXPERIENCE being served - the site the app
    declared for the portal on a portal request, the staff Session site otherwise
    (site 0 when sessionless in CLI or a task) - enforces the blocklist for
    non-transactional categories, applies the dev-site redirect, queues the row and
    kicks a prompt background drain (Task::dispatch, coalesced by #[Exclusive]) in
    every context except a test run.

    The site is not cosmetic: it stamps the row AND drives the opt-out lookup, so
    asking the staff facade on a portal request would file the message under the
    wrong tenant and consult the wrong blocklist. Call Session::set_site_id() first
    when a task must target a particular tenant. See: rsx:man portal.

CATEGORIES
    TRANSACTIONAL (1)  Always delivers. Ignores opt-out (codes, alerts).
    NOTIFICATION  (2)  Respects opt-out. Default.
    MARKETING     (3)  Respects opt-out.

    Constants: Rsx_Sms::TRANSACTIONAL / NOTIFICATION / MARKETING, matching
    Sms_Queue_Model::CATEGORY_*.

BLOCKLIST / OPT-OUT (STOP)
    Per-number preferences live in sms_recipients, unique per site_id + number. A
    non-transactional message to an opted-out number is recorded as a BLOCKED row
    rather than silently dropped.

        Rsx_Sms::block_all($number)          // STOP: all non-transactional
        Rsx_Sms::block($number, $category)
        Rsx_Sms::unblock($number, $category)
        Rsx_Sms::is_blocked($number, $category)

    An app's carrier "STOP" handler calls block_all(); "START" unblocks.

STATUSES
        Id  Status       Meaning
        --  -----------  --------------------------------------------------------
        1   Pending      Queued; sendable when next_attempt_at is null or past.
        2   Sending      Claimed by a drain right now.
        3   Sent         A provider accepted it. Unreachable until one exists.
        4   Failed       Terminal: the provider-error attempt cap, or a build bug.
        5   Blocked      Never queued: the number had opted out of this category.
        6   Suppressed   Recorded, deliberately not delivered - no provider, or a
                         dev host left no deliverable number. Terminal, and NOT a
                         failure.

    Columns mirror the mail queue: attempt_count (a first send IS an attempt),
    next_attempt_at, last_attempt_at, last_error, transport, transport_response,
    dedupe_key (unique per site), dev_original_to.

QUEUE PROCESSING
        php artisan rsx:task:run Sms_Queue_Service send_pending_queue

    #[Task] #[Exclusive] #[Schedule('every minute')], needing the ordinary task cron:

        * * * * * php artisan rsx:task:process

    In 'disabled' the pass logs one line and returns without touching anything -
    no claim, no reclaim, no aging.

    Otherwise each pass RECLAIMS anything left SENDING by a drain that died
    mid-message (#[Exclusive] proves no other runner exists, so no age threshold
    is needed; the attempt is not counted), then claims PENDING rows one at a time
    with a conditional UPDATE and drives each to a terminal status.

    Retention: Sms_Queue_Service::cleanup, #[Schedule('daily at 3am')], deletes
    whole rows in a terminal status older than rsx.sms.retention_days (30).

DEV SITE SMS SAFETY
    On a dev host (Rsx::is_dev_site() - the hostname contains '.dev.') outbound
    numbers are gated, mirroring the email layer:

        SMS_DEV_NUMBER_WHITELIST     comma-separated numbers that deliver as-is
        SMS_DEV_CATCHALL_NUMBER      everything else redirects here, the real
                                     number recorded in dev_original_to

    Neither one matching means nothing is deliverable from this host, and the row is
    written SUPPRESSED at enqueue time with the reason "dev site: no whitelist match
    and no catchall".

CONFIGURATION
    config('rsx.sms.*'):

        delivery            SMS_DELIVERY, default 'suppressed'. suppressed | disabled
                            only - see DELIVERY MODES above. Leave it alone until a
                            provider exists.
        provider            the sending service, once one is wired: twilio |
                            aws_sns | vonage | messagebird | plivo | sinch | telnyx
                            | infobip | bandwidth. Inert today.
        from_number         sending number / sender id.
        credentials         provider-specific auth (Twilio SID/token, AWS
                            key/secret/region, Vonage key/secret, generic
                            api_key/api_secret/auth_token). Secrets in .env.
        retry               ['attempts' => 3, 'delay_minutes' => 3] - the
                            provider-error policy, mirroring rsx.mail.retry.
        retention_days      30
                            (no stale_after_days - see DELIVERY MODES)
        dev_site            catchall_number, number_whitelist (above)

SMS LOG (read model)
    Sms_Queue_Model::fetch($id) is an #[Ajax_Endpoint_Model_Fetch], login-gated,
    loading one record for a developer-facing SMS log - full fields, no aliasing,
    plus status_id__label/__badge and category_id__label/__badge.
