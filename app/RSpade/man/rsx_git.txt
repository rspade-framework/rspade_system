NAME
    rsx:git - the git proxy that keeps the framework submodule in step

SYNOPSIS
    php artisan rsx:git <any git command>

    Inside the RSpade container /usr/local/bin/git routes here automatically,
    so `git` means this without anyone having to type it.

DESCRIPTION
    IT DOES EXACTLY ONE THING. After any git operation that can move the
    RECORDED revision of the system/ submodule, it makes the submodule agree
    with it. Everything else is passthrough - same output, same exit code,
    same argv, nothing announced.

    THE PROBLEM. system/ is a git submodule. When a colleague updates the
    framework and you pull their commit, git updates the recorded revision and
    does not touch the submodule's working tree. Nothing fails, nothing is
    printed, and you are now running a framework version your project does not
    claim to use. `git status` shows ` M system` and `git submodule status`
    prefixes a `+`, but nobody reads either before every command.

    The usual answer is to tell everyone to type `git pull --recurse-submodules`
    forever. A rule everybody has to remember is not a solution; this is.

WHAT IT DOES WHEN THE REVISIONS DISAGREE
        maintenance window up
          -> reset the submodule hard, discard untracked files
          -> rsx:clean (caches)
          -> fetch, if the recorded revision is not in the local object store
          -> check out the recorded revision
          -> rebuild (manifest + bundles)
        maintenance window down
        -> report pending migrations

    The window matters: replacing the framework under a live php-fpm is
    exactly the situation maintenance mode exists for.

    The submodule reset is performed DIRECTLY, not through rsx:clean. rsx:clean
    does the same thing and is still called for the caches, but it needs
    artisan to boot - and the checkout must not depend on that. A developer
    whose tree is too broken to run php is the developer most likely to be
    pulling a fix.

WHICH SUBCOMMANDS TRIGGER IT
        pull merge rebase cherry-pick revert checkout switch restore reset stash

    THE LIST IS THE WHOLE POLICY: these are the operations that rewrite what
    HEAD points at, and therefore the gitlink recorded for system/. Anything
    else execs git immediately.

    `restore` and `checkout` are included because they CAN move it. When they
    do not, the before/after comparison costs one rev-parse and does nothing.

    The classifier steps past git's global options: `git -C x -c k=v
    --no-pager pull` is a pull, not a `-C`.

WHERE IT GETS OUT OF THE WAY
    Four conditions, each of which makes it exactly git:

      * The framework monorepo (IS_FRAMEWORK_DEVELOPER=true). There system/
        IS the work being done, not a checkout of it.
      * No git, or not a git repository.
      * system/ is not a submodule - a project not yet converted.
      * The subcommand is not in the list above.

    FAIL-OPEN. This wraps every git call for every downstream app, so a bug
    here must never brick git. Anything unexpected falls through to plain git
    with the original argv.

A CONFLICTED REVISION IS REPORTED, NEVER RESOLVED
    When both sides of a merge moved the recorded revision, git cannot choose
    and neither does this. Which framework release to run is a decision with
    consequences - a release can carry migrations - so the proxy prints the
    three commands that resolve it and changes nothing:

        git checkout --theirs -- system    # take the incoming revision
        git checkout --ours   -- system    # keep yours
        git add system

    Then rsx:framework:pull brings system/ into line.

    The vendored-era proxy tried to settle this automatically by comparing
    the two sides' release markers. That cleverness is what a submodule makes
    unnecessary; the marker itself is retired.

IT DOES NOT HAVE TO BE EXHAUSTIVE
    bootstrap/rsx_submodule_sync.php refuses to boot when the recorded
    revision and the checkout disagree, whatever caused it - an IDE's git,
    /usr/bin/git directly, a script that never heard of this proxy.

    So the proxy is the CONVENIENCE and the guard is the CORRECTNESS. That is
    why the proxy is allowed to be 300 lines you can read rather than 1,500
    you have to trust.

THE THREE LAYERS
    /usr/local/bin/git          the shim. Bails to /usr/bin/git on
                                re-entrancy, outside-the-project, or no-PHP.
                                Otherwise execs `php artisan rsx:git`.
    php artisan rsx:git         intercepted PRE-BOOT in system/artisan, so it
                                never loads Laravel and works on a tree too
                                broken to boot.
    system/bin/rsx-git.sh       the proxy itself.

CWD FIDELITY
    system/artisan does chdir(__DIR__), so by the time the proxy runs, php has
    destroyed the directory every relative pathspec was written against.

    The shim exports RSX_GIT_CWD before php can do that, and the proxy
    restores it. Without the shim the anchor is the project root - what a
    human's relative pathspec is written against - and only the artisan chdir
    is undone: a cwd the caller genuinely chose is left alone.

    The failure this prevents is the worst shape there is: `rsx:git log --
    rsx/foo.php` matching nothing and exiting 0, an audit command answering
    "no history" for a file that has history.

WHAT IT NO LONGER DOES
    Under the vendored model this script was 1,553 lines. It excluded system/
    from status/diff/add with pathspecs, unstaged system/ paths out of
    commits, rewrote `commit -a`, and ran a release-reconciliation phase over
    both sides of a merge.

    A submodule makes all of that structural: the framework contributes ONE
    gitlink to the application's index, and `ignore = dirty` in .gitmodules
    hides the build's own churn without anyone hand-rolling a pathspec.

    `dirty` hides the CHURN and not the POINTER: a framework update stays
    visible in status, diff and `show --stat`, which is the one thing about
    system/ anybody reviews. Do not add a repo-wide
    `[diff] ignoreSubmodules = all` to .git/config - it hides the pointer too,
    and every other gitlink with it. The 080 environment update unsets it and
    the "Submodule Visibility" rsx:health row reports it.
