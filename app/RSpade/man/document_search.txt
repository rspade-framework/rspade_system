DOCUMENT_SEARCH(1)                RSpade Manual                DOCUMENT_SEARCH(1)

NAME
    document_search - document text extraction, full-text search, and in-browser
    document preview (Document_Preview + pdf.js + PDF renditions, and its
    extracted-text sibling Document_Text_Preview)

SYNOPSIS
    The pipeline (background, framework-internal):
        Document_Render_Service::render_pending   ONE worker: PDF rendition + text
                                                  (#[Exclusive], every 10 minutes,
                                                   kicked on upload)
        config('rsx.search.*')  config('rsx.preview.*')  config('rsx.libreoffice.*')

    Search (app-facing):
        File_Attachment_Model::search_text($query [, $mode])   // Eloquent Builder
        Search_Index_Model::search_ranked($query [, $mode])    // + relevance score
        $attachment->get_extracted_text()                      // ?string
        $attachment->get_extraction_status()                   // ?int (null = pending)

    Preview (in-browser):
        <Document_Preview $attachment_id=this.args.id />        // the picture
        <Document_Text_Preview $attachment_id=this.args.id />   // the extracted text
        config('rsx.preview.*')   File_Preview_Controller  (/_preview/pdf/:key)

    CLI:
        php artisan rsx:search:reindex --status
        php artisan rsx:search:reindex --all | --failed | --below-version=N
                                       | --storage=ID | --attachment=ID
        php artisan rsx:documents:status | :failed | :rerender    (rsx:man documents)
        php artisan rsx:health         # verifies soffice / poppler / fonts

DESCRIPTION
    RSpade extracts the text of uploaded documents into a FULLTEXT-searchable store
    and renders documents in the browser, both as framework-core features every app
    inherits. Neither requires any app wiring: an upload is queued for extraction
    automatically, and <Document_Preview> renders a PDF/Office/image attachment with
    no per-format branching in the page. <Document_Text_Preview> is its sibling: same
    attachment, same waiting-then-swap behavior, but it renders the extracted TEXT.

    Both systems key their work on the DEDUPLICATED blob (File_Storage_Model), not on
    the logical attachment. Identical bytes are extracted once and converted to a PDF
    rendition once, no matter how many attachments reference them.

    Unlike Laravel, which ships no document pipeline (you would wire Scout + a driver
    for search and a JS library by hand for preview), RSpade discovers the extractor,
    viewer, and health inventory through the manifest and exposes three #[OnEvent]
    resolve chains so an app can override any stage without touching core.

    ONE WORKER OWNS BOTH. As of 2026-08-22 text extraction and PDF renditions are not
    two systems sharing a slot pool - they are two products of a single background
    pass. Document_Render_Service::render_pending converts a document to PDF ONCE and
    extracts its text in the same iteration; the thumbnail pipeline then rasterizes
    that same rendition. Before this, one Word document was converted three times (a
    thumbnail, a rendition, a text pass) by three callers competing for a two-slot
    semaphore inside web requests. See rsx:man libreoffice.

    The consequence a page must know about: an Office document's text AND its picture
    AND its preview all appear a few seconds AFTER the upload, not during it.

EXTRACTION PIPELINE
    TWO FACTS, kept apart. Every File_Storage_Model blob carries is_indexed, which
    says whether its text is OWED; the _search_indexes row says what the LAST
    attempt FOUND:

        no row, is_indexed = 0          never attempted
        EXTRACTED / UNSUPPORTED         a definitive answer; is_indexed = 1
        FAILED, is_indexed = 0          an attempt failed and the worker will try
                                        again
        FAILED, is_indexed = 1          failed for good - the attempts are spent;
                                        re-queued only by rsx:search:reindex

    There is NO stored PENDING state: a row is written only AFTER an attempt, so its
    status_id is always one of three outcomes:

        EXTRACTED     text pulled (may be empty - a text-free/all-image PDF is a
                      VALID empty extraction, not a failure; OCR is out of scope).
                      Text over config('rsx.search.max_text_bytes') is TRUNCATED to
                      the cap and RECORDED (row metadata truncated=true +
                      original_bytes) - still EXTRACTED, never a silent partial
        FAILED        an extractor threw a real, RETRYABLE fault (non-zero exit, a
                      corrupt source), the stage ran past its bound, or the process
                      running it died; the error is stored on the row. The worker
                      retries it - see below. A missing binary, an absent sandbox
                      image or an unreadable source found by the extractor's
                      soft_failure() check BEFORE the attempt is recorded FAILED
                      too, with that reason, but charges no attempt (CUSTOM
                      EXTRACTORS below)
                      A SCANNED PDF is the case that surprises people: it is
                      application/pdf, so it HAS an extractor, pdftotext runs, and
                      it succeeds - yielding EMPTY text. It records EXTRACTED with
                      no content, NEVER UNSUPPORTED and never FAILED, and it will
                      never match a search. Only a standalone image file (which has
                      no extractor at all) is UNSUPPORTED. There is no OCR.
        UNSUPPORTED   no extractor is registered for the mime (image, zip, ...);
                      LibreOffice is disabled for an Office mime; OR the source is
                      unextractable BY DESIGN (a password-protected / encrypted
                      document) - that reason is stored in the row's error column,
                      because a retry can never help (unlike FAILED)

    Draining. Document_Render_Service::render_pending is #[Exclusive] (at most one
    pass runs cluster-wide) and #[Schedule('every 10 minutes')]. The queue is ONE
    column on the blob, _file_storage.process_due_at: a blob that owes a rendition,
    its text, or both carries the time it may next be attempted, and the worker
    takes the earliest due blob, one per iteration, until none is due. A prompt kick
    (Task::dispatch on blob creation/materialization and on a blob entering PENDING)
    drains uploads without waiting for the sweep.

    ATTEMPTS, RETRIES AND BOUNDS. Each blob is processed in a child process of its
    own. The attempt is charged before it starts; a FAILED extraction leaves
    is_indexed at 0 and is tried again config('rsx.documents.retry_after_minutes')
    (30) later, up to config('rsx.documents.max_attempts') (3) attempts, after which
    the row stays FAILED and is_indexed becomes 1. The render and the extraction of
    one blob share that counter. The whole computation of a blob's text - an
    application's document.extract_text handler, the external binaries and the
    in-process readers alike - runs under ONE wall-clock bound,
    config('rsx.documents.stage_seconds') (20); past it the attempt is recorded
    FAILED with "text extraction exceeded 20 seconds". A SOFT failure - the
    extractor's soft_failure() check naming a tool or source that is not available -
    is recorded FAILED with its reason but charges nothing, and is checked again on
    a backoff that doubles from 30 minutes up to a week, indefinitely. Full rules:
    rsx:man documents, THE WORK QUEUE.

    Search_Index_Service::extract_storage($storage, ?$rendition_path) is the unit of
    work the worker's child runs. It is COMMAND-LINE ONLY and throws from a web
    request; code that wants a blob processed now calls
    Document_Render_Service::process_storage($storage) (rsx:man documents,
    APPLICATION CODE AND THE QUEUE).

    Two master switches, governed separately. config('rsx.search.enabled') governs
    EXTRACTION and is also the kick switch: when false, no worker is spawned on
    upload, and a blob that owes ONLY its text is deferred - offered again one retry
    interval later, no attempt charged, existing rows untouched. (A pass that runs
    for a blob's rendition extracts whatever text that blob owes as well.)
    config('rsx.libreoffice.enabled') governs RENDERING through soffice. A box with
    LibreOffice off still extracts PDFs and plain text, and a document LibreOffice
    renders stays PENDING, deferred the same way, until the switch comes back. (If
    both are off the worker returns immediately.)

    Re-extraction. Bump config('rsx.search.extractor_version') when an extractor
    changes in a way that should re-produce existing text, then:

        php artisan rsx:search:reindex --below-version=N

    re-queues every blob indexed by an older generation (is_indexed = 0, due now, no
    attempts charged). The cron/kick re-extracts them one at a time.

    Office documents route by FAMILY, because no single route covers them all:

        Writer   (doc/docx/odt/rtf/...)  pdftotext over the PDF RENDITION the same
                                         worker pass just produced - no soffice run of
                                         its own. With no rendition available (the LRU
                                         cleanup evicted it) it falls back to the
                                         registry's Libreoffice_Text_Extractor and its
                                         Writer-only 'txt:Text (encoded):UTF8' filter;
                                         with LibreOffice disabled that route records
                                         UNSUPPORTED rather than calling soffice.
        Calc     (xls/xlsx/ods/...)      --convert-to fods (flat XML, ONE file, ALL
                                         sheets), then a STREAMING XMLReader pass
                                         emits each sheet's name + every cell's text
        Impress  (ppt/pptx/odp/...)      --convert-to fodp (flat XML), same pass over
                                         each slide's text

    Net soffice runs per document: ONE for a Writer document (the rendition, reused for
    text and for the thumbnail), TWO for a spreadsheet or presentation (the rendition
    plus its flat-XML pass). It was three for all of them.

    The 'Text (encoded)' filter is Writer-ONLY: it silently produces NO output for a
    Calc or Impress document (so every spreadsheet/presentation used to FAIL). The
    flat-XML route is streamed (never DOM-loaded) so a 170-sheet workbook does not
    blow memory - the reader stops once assembled text passes the byte cap and the
    service truncates precisely (see the truncation note above).

    Dedup and site scoping. _search_indexes rows are keyed on File_Storage_Model
    (indexable_type = 'File_Storage_Model', indexable_id = the blob id) and carry NO
    site_id - extraction is cross-site because the deduplicated blob is cross-site.
    Site scoping happens at the ATTACHMENT join: search_text() returns a
    File_Attachment_Model builder the app constrains with its own site/permission
    filters.

    External / OneDrive residency. When bytes live in an external system (the
    attachment-handler seam, rsx:man file_upload), the blob is only queued once it is
    MATERIALIZED (store_blob() flips is_indexed on and kicks the drain). Until then the
    attachment has no resident blob and get_extraction_status() reports null (pending)
    WITHOUT forcing a materialization. An app that wants text sooner can either force
    materialization or intercept document.extract_text (below).

CUSTOM EXTRACTORS
    config('rsx.search.extractors') maps a mime pattern to a
    Rsx_Text_Extractor_Abstract, resolved for the blob's pipeline mime by
    Rsx_Mime_Map (rsx:man documents, MIME MAP PRECEDENCE): an application entry
    beats every framework entry, and inside a layer the most specific pattern wins.
    A mime matching nothing is UNSUPPORTED. An application adds a type, or replaces
    the framework's extractor for one, in rsx/resource/config/rsx.php:

        'search' => ['extractors' => [
            'application/x-dwg' => 'Cad_Text_Extractor',
        ]],

    THE CONTRACT (static methods; extend Rsx_Text_Extractor_Abstract DIRECTLY - it
    is #[Monoprogenic]):

        extract(string $source_path, string $mime): string
            The text, UTF-8. An empty string only for a document that genuinely has
            none (EXTRACTED). Throw on any failure - a HARD failure, charged. Throw
            Rsx_Extraction_Unsupported_Exception($reason) for a source that cannot
            be extracted BY DESIGN (encrypted): UNSUPPORTED, not a failure. Runs in
            the worker's child under the text-extraction stage bound; spawn a binary
            with Document_Stage_Bound::run_process($argv).

        soft_failure(string $source_path): ?string          default null
            The opt-in soft check, asked BEFORE an attempt (and on every view of a
            soft-failed preview): null = proceed; a string = why the attempt cannot
            succeed on this box now. Recorded on the index row, NOT charged. It must
            only look - never run the tool or parse the document. The protected
            helper source_unreadable($path) is the source check;
            Document_Soft_Checks spells the framework's tool checks.

            class Cad_Text_Extractor extends Rsx_Text_Extractor_Abstract
            {
                const BINARY = '/usr/local/bin/dwg2text';

                public static function extract(string $source_path, string $mime): string
                {
                    $process = Document_Stage_Bound::run_process([self::BINARY, $source_path]);
                    if (!$process->isSuccessful()) {
                        throw new \Exception('dwg2text failed: ' . trim($process->getErrorOutput()));
                    }

                    return $process->getOutput();
                }

                public static function soft_failure(string $source_path): ?string
                {
                    if (!is_executable(self::BINARY)) {
                        return 'dwg2text is not installed or not executable';
                    }

                    return static::source_unreadable($source_path);
                }
            }

    The framework's checks: Pdftotext_Text_Extractor - pdftotext found (sandboxed:
    the docker client and an operator's own image present), then the source;
    Libreoffice_Text_Extractor - soffice runnable, then the source;
    Plain_Text_Extractor and Spreadsheet_Text_Extractor - the source readable.

    TWO THINGS ARE DECIDED AHEAD OF THE REGISTRY. A word-processing document (doc,
    docx, odt, rtf) whose PDF rendition is available is read by pdftotext from that
    rendition, whatever the registry maps its mime to. And a
    document.extract_text handler (FILTER CHAINS below) runs before the registry in
    a real pass - but the soft check cannot run a handler, so it asks the
    registry's extractor for the type; a type an application extracts ONLY through
    a handler is checked against whatever extractor the registry maps it to.

FILTER CHAINS (the app extension surface)
    Three Rsx::trigger_resolve() chains let an app override or extend a document stage
    without editing core. trigger_resolve semantics: handlers run in priority order,
    each receiving the SAME payload; the FIRST to return a non-null value WINS and the
    chain stops; if every handler returns null (declines), the framework runs its own
    terminal default. See rsx:man event_hooks (RESOLVE EVENTS).

    document.extract_text  (Search_Index_Service::extract_storage)
        Runs INSIDE the render worker's child process for the blob - a command-line
        process, never a web request - and INSIDE THE TEXT-EXTRACTION STAGE BOUND:
        the handler and whatever it calls share config('rsx.documents.stage_seconds')
        (20 seconds) with the rest of the extraction. A handler still running at the
        bound is interrupted where it stands (a Document_Stage_Timeout_Exception
        thrown from the alarm), the attempt is recorded FAILED and the worker
        retries it. A handler that calls a slow external service either answers
        inside the bound or the site raises it. 'path' is the SOURCE BLOB - the
        rendition shortcut is applied after the chain declines, so a handler always
        sees the original document.
        Payload:  ['storage' => File_Storage_Model, 'path' => string, 'mime' => string]
        Return:
            null                                decline -> framework extractor registry
            string                              the extracted text  (-> EXTRACTED)
            ['status' => 'unsupported', 'error' => ?string]   (-> UNSUPPORTED)
            ['status' => 'failed', 'error' => string]         (-> FAILED)
            (anything else fails loud)

            #[OnEvent('document.extract_text')]
            public static function extract_special($data) {
                if ($data['mime'] !== 'application/x-special') return null; // decline
                return Special_Lib::to_text($data['path']);                 // extracted
            }

    document.preview_rendition  (File_Preview_Controller::pdf_rendition)
        Runs AFTER the authorization gates (below). Overrides how an attachment becomes
        a PDF rendition for pdf.js. CONTRACT UNCHANGED, but the framework path behind
        it is now SERVE-ONLY: it serves a PDF blob as-is, or the rendition the
        background worker already produced, and 404s (naming the render state) for a
        document whose rendition is not RENDERED yet. It never converts. A handler
        that DOES convert on demand still works exactly as before - it simply no longer
        has a framework twin doing the same thing.
        Payload:  ['attachment' => File_Attachment_Model, 'request' => Request]
        Return:
            null                       decline -> framework rendition pipeline
            Response                   takeover - the handler serves the response
            ['path' => <abs pdf>]      the framework serves that PDF file inline
            ['unsupported' => true]    415 - no PDF rendition for this attachment
            (anything else fails loud)

            #[OnEvent('document.preview_rendition')]
            public static function convert_cad($data) {
                if ($data['attachment']->file_extension !== 'dwg') return null; // decline
                return ['path' => Cad_Service::to_pdf($data['attachment'])];    // serve
            }

    document.thumbnail_render  (File_Attachment_Controller::_render_thumbnail_data)
        STILL RUNS FIRST - ahead of the rendition path and ahead of the renderer
        registry (rsx:man thumbnails). Overrides the "bytes -> raster" step. Note the
        rendition case: for a RENDERED document the framework would rasterize page 1
        of the PDF rendition, but the chain runs BEFORE that decision and 'path' is
        always the SOURCE BLOB, never the rendition - so a handler that takes over an
        Office mime behaves exactly as it did, and one that declines gets the
        rendition path automatically. The chain is not consulted at all for a PENDING
        or FAILED blob: those serve the extension-icon placeholder without entering
        the render path.
        Payload:  ['attachment' => File_Attachment_Model, 'path' => string,
                   'type' => string, 'width' => int, 'height' => ?int]
        Return:
            null                       decline -> framework renderer registry
            string                     WebP bytes, served as-is
            ['unsupported' => true]    render the generic extension icon
            (anything else fails loud)

            #[OnEvent('document.thumbnail_render')]
            public static function preview_service($data) {
                if (!My_Preview::handles($data['attachment'])) return null;    // decline
                return My_Preview::webp($data['attachment'], $data['width']);  // bytes
            }

SEARCH API
    File_Attachment_Model::search_text(string $query, string $mode = 'BOOLEAN')
        Returns an Eloquent Builder of attachments whose extracted text matches $query.
        Runs a FULLTEXT MATCH...AGAINST over _search_indexes (EXTRACTED rows only),
        then constrains a File_Attachment_Model query to the matching blobs. $mode is
        'BOOLEAN' (default, supports +term -term "phrase") or 'NATURAL LANGUAGE'. The
        app composes site scoping, joins, and ordering onto the returned builder:

            $rows = File_Attachment_Model::search_text('+contract -draft')
                ->where('site_id', Session::get_site_id())
                ->orderByDesc('created_at')
                ->get();

    Extracted text is also reachable EXTERNALLY, per file, at
    GET /api/v1/files/:key/text (Bearer key; 409 while extraction is pending, and
    a text_status of pending/available/error/unsupported on
    GET /api/v1/files/:key). There is no external SEARCH endpoint - search_text()
    is site-unscoped by construction and the scoping is the app's to compose, so
    exposing it is an application decision. See rsx:man external_api.

        Dedup note: one matching blob may back several attachments, so the builder can
        yield multiple rows per blob - exactly what a staff-wide Files index wants.

    Search_Index_Model::search_ranked(string $query, string $mode = 'BOOLEAN')
        The same query as search(), with MySQL's relevance score SELECTED as
        `relevance` and the builder pre-ordered by it descending. search() answers
        "does this match?", which is all a filter needs; search_ranked() answers
        "which of these matches best?", which is what a results LIST needs - without
        it a page either re-derives a worse score in PHP or hand-writes
        MATCH...AGAINST in app code.

            $rows = Search_Index_Model::search_ranked('contract')
                ->where('indexable_type', 'File_Storage_Model')
                ->where('status_id', Search_Index_Model::STATUS_EXTRACTED)
                ->get();
            // $rows[0]->relevance is a float, highest first

        It returns an ordinary Builder, so further where()/join()/pagination compose
        normally and keep both the score and the ordering. An orderBy() of your own
        APPENDS to the ranking rather than replacing it - call reorder() first to
        discard it.

        The MATCH expression appears in both the select and the where. MySQL
        recognises the identical expression and performs ONE full-text scan, so the
        duplication costs no extra index work.

        THE SCORE IS NOT NORMALISED. In BOOLEAN mode it is comparable only WITHIN one
        result set and is meaningless across queries: order by it, never threshold on
        it and never render it as a percentage. In NATURAL LANGUAGE mode a term
        appearing in more than 50% of the rows scores zero and drops out of the match
        set entirely - a ranking artifact of the mode, not of this method.

        The rows are index rows, not attachments: relevance belongs to the
        deduplicated blob, and one blob can back several attachments. Map
        indexable_id (a File_Storage_Model id) to your own results and sort them.
        See the reference app's Dev_Document_Preview_Controller::search_text_ranked()
        (system/app/RSpade/resource/reference_app/app/dev/document_preview/).

    $attachment->get_extracted_text(): ?string
        The extracted text, or null if the blob has not been indexed yet. Routes
        through resolve_storage() (materializes external bytes if needed). Returns ''
        for an indexed blob that yielded no text (FAILED / UNSUPPORTED / text-free) -
        use get_extraction_status() to distinguish.

    $attachment->get_extraction_status(): ?int
        The Search_Index_Model::STATUS_* id, or null if pending. Reads file_storage_id
        directly and NEVER materializes external bytes (a non-resident attachment reads
        as pending).

    File_Storage_Model->get_search_index(): ?Search_Index_Model
        The raw index row for a blob (content, status_id, error, extraction_method,
        extractor_version, metadata), or null if never attempted.

DOCUMENT_PREVIEW COMPONENT
    <Document_Preview> renders a real, in-browser preview of an attachment by resolving
    a viewer component from the server (File_Preview_Controller::get_preview_info) and
    dispatching to it - no per-format branching in the page.

        <Document_Preview $attachment_id=this.args.id />
        <Document_Preview $attachment_id=42 $page=3 $width=600 $height=800 />
        <Document_Preview $attachment_id=42 $fit="contain" />

    Args:
        $attachment_id  (required) File_Attachment_Model id. Throws if absent.
        $page           (optional) initial page for paged viewers (default 1).
        $width/$height  (optional) fixed px; omitted -> fills the container (100%).
        $fit            (optional) how a paged page is scaled inside the frame.
                        "width" (default) or "contain"; anything else THROWS.

    FIT MODES. $fit answers the one geometry question the host cannot express from
    outside: how the rendered page is scaled inside the space the host gave it.

        width    (default) scale to the frame's WIDTH:
                 scale = frame_width / page_width. A portrait page in a wide, short
                 pane is taller than the pane and the frame scrolls. This is the
                 historical behaviour and it is unchanged.
        contain  scale so the ENTIRE page is visible:
                 scale = min(frame_width/page_width, frame_height/page_height).
                 The canvas is then sized in EXPLICIT CSS px (not width:100%), so the
                 bitmap paints at exactly the size it was rasterized for.

    $fit="contain" REQUIRES A HOST WITH BOUNDED HEIGHT - it is dividing by that
    height. Give the component a $height, or mount it in an element that has a real
    height of its own. Given a height:auto host there is nothing to divide by, and
    contain FALLS BACK to the width fit rather than rendering at a zero scale. The
    height is measured on .Document_Preview__frame, the box the host's dimensions
    actually land on; the viewer's own root has no height but the canvas's, so
    measuring it would be circular.

    Only PAGED viewers act on $fit. Image_Viewer and Icon_Viewer already fit both
    axes by CSS and are not given it. An APP-registered viewer receives it in its
    instantiation args and may do as it likes with it.

    RESIZE. A paged viewer observes the frame (a ResizeObserver) and RE-RENDERS the
    current page when the frame's box changes - so a pane that grows re-rasterizes
    at the new size instead of stretching the old bitmap up. The callback is
    debounced (200ms) so a drag or an animated column collapse issues one re-raster,
    not one per frame; a box that did not actually move renders nothing. Both fits
    re-render: "width" re-rasterizes on a width change, "contain" on either axis.

    Events OUT (listen on the Document_Preview; the active viewer's are re-emitted):
        'preview_loaded' {attachment_id, state, render_status,
                          pages, width, height, ratio}
        'page_changed'   {page}

        'preview_loaded' is emitted for WHATEVER ends up in the frame - a viewer's
        document, "Preparing preview...", the failed notice, the unavailable card -
        and again each time that is replaced. The guarantee, the state vocabulary
        and late subscription are THE PREVIEW_LOADED EVENT below.

        pages is the document's page count (1 for an unpaged viewer, 0 when no
        viewer is showing a document). width/height/ratio describe the page
        CURRENTLY RENDERED, not the document: 'preview_loaded' is emitted again
        after every page change, ahead of 'page_changed', so on a
        mixed-orientation file they change as the reader pages through it. Read
        'ratio' as "the shape of the page you are looking at", never as a
        document-wide fact. An unpaged viewer with no geometry (text, markdown, a
        grid, the icon) omits the three; a state with no document carries zeros.

        The load event is 'preview_loaded', NOT 'loaded' - 'loaded' is a reserved
        jqhtml lifecycle event fired internally with no payload, so a custom event may
        never reuse it (nor create/load/ready/render/rendered/stop). See rsx:man jqhtml.

    Methods (delegate to the active viewer; no-op before it is ready):
        set_page(n) / get_page() / get_pages()

    RENDER STATES. get_preview_info() carries the blob's render_status_id, and
    <Document_Preview> subscribes to the attachment in on_create() exactly as
    <Attachment_Thumbnail> does, so it repaints itself when the render lands:

        PENDING       "Preparing preview..." - the worker has not converted it yet.
                      No rendition URL is returned, so the viewer is never asked to
                      load one early.
        FAILED, with  "Preparing preview..." too: this view set a retry in motion
        render_retrying (rsx:man documents, THE WORK QUEUE - a soft failure whose
                      cause has gone, or a hard one whose retry interval has
                      passed), and the worker's frame brings the outcome.
        FAILED        A failed state. The render_error is NEVER sent to the browser;
                      the operator reads it with rsx:documents:failed.
        RENDERED      urls.rendition is present and Pdf_Viewer loads it.
        NOT_REQUIRED  A PDF or an image: served directly, as always.

    When the worker settles the blob it emits a realtime frame on every attachment
    referencing it, and the open preview swaps from "Preparing preview..." to the
    document with no reload. On a realtime-disabled box the preparing state persists
    until the next navigation - there is deliberately no polling.

    Preview-unavailable state. An attachment degraded at upload (an image whose bytes
    could not be parsed - see rsx:man file_upload, UNPARSEABLE IMAGE DEGRADE) carries
    preview_unavailable=true. get_preview_info() surfaces the flag and <Document_Preview>
    renders a "Preview unavailable" state instead of a viewer (pipeline_mime() is
    application/octet-stream, so it would resolve to Icon_Viewer regardless).

    The same card, with no icon and no file name, is what a record that cannot be
    read paints - a deleted attachment, or one this user may not see (the endpoint
    answers both alike). It is a state of the component, never a thrown error.

    Viewer registry. get_preview_info() resolves the viewer by mime via
    config('rsx.preview.viewers'), a map of mime glob -> viewer component simple
    name resolved by Rsx_Mime_Map (rsx:man documents, MIME MAP PRECEDENCE): an
    application entry beats every framework entry, and inside a layer an exact mime
    beats a glob and a longer glob beats a shorter one. The framework ships six
    viewers and a terminal '*' entry so every mime resolves:

        Pdf_Viewer     PDFs, and every type whose renderer produces a PDF
                       rendition (rsx.documents.renderers - the Office documents).
                       Lazy-loads pdf.js and paginates on a canvas.
        Spreadsheet_Viewer
                       the workbook mimes, as a GRID - the HTML rendition
                       PhpSpreadsheet produces, in a sandboxed iframe. Its globs are
                       longer than the generic Office patterns, which would
                       otherwise take a workbook to a PDF of LibreOffice's print
                       view.
        Image_Viewer   image/*  (natural-dimension preview).
        Markdown_Viewer
                       text/markdown - the file rendered as the DOCUMENT its author
                       wrote (GitHub-flavoured: headings, tables, task lists, fenced
                       code, autolinks), not as its source characters. Registered
                       for the exact mime text/markdown, which beats the text/*
                       glob that would otherwise take it. The markup
                       comes from the Ajax endpoint get_markdown_html, rendered per
                       request - there is no rendition on disk, no background worker
                       and therefore no waiting state. TWO INDEPENDENT SANITISING
                       LAYERS produce it (Markdown_Rendition): the CommonMark parser
                       configured with html_input=strip and allow_unsafe_links=false,
                       then HTMLPurifier over the OUTPUT with an explicit allowlist of
                       exactly the elements GFM emits. Either alone would be enough;
                       they fail differently, which is the argument for both.
        Text_Viewer    text/*   (the file's own characters in a scrolling monospace
                       frame). IT READS THE EXTRACTION, not the inline URL: the text
                       pipeline has already decoded the file's charset and capped it at
                       rsx.search.max_text_bytes, where raw bytes would arrive undecoded
                       and unbounded and would need their own realtime wiring to notice
                       the pipeline finishing. The cost is stated in the UI - a
                       just-uploaded file shows "(Extracting Text...)" for a second or
                       two, and "(This file is empty)" is a distinct state from
                       "(Text Unavailable)" because an empty file is a fact about the
                       file, not a fault in the preview.
        Icon_Viewer    terminal - the generic extension icon for anything else.

    The '*' entry is consulted only when nothing else matches. An application adds
    a viewer for a mime the framework does not cover, or replaces the framework's
    viewer for one it does, by listing the pattern in rsx/resource/config/rsx.php
    ('preview' => ['viewers' => ['video/*' => 'Video_Viewer']]). A type an
    application renders to a PDF with a renderer of its own is listed here as
    'Pdf_Viewer' (rsx:man documents, REPLACING A FRAMEWORK PIPELINE FOR A FILE
    TYPE).

    A text/* attachment therefore classifies as FILE_TYPE_DOCUMENT: it is previewable in
    exactly the way a PDF is. FILE_TYPE_TEXT remains a declared enum value that nothing
    assigns.

    An app adds or overrides viewers by merging config('rsx.preview.viewers') in
    rsx/resource/config/rsx.php. A built-in viewer is rendered directly by the
    Document_Preview template; every other viewer name (Spreadsheet_Viewer,
    Markdown_Viewer, and any APP-registered one) is instantiated dynamically into
    the host element, once Document_Preview is ready, with {attachment_id, url,
    extension, file_name, page, fit}.

    THE VIEWER CONTRACT. A viewer is an ordinary jqhtml component that takes those
    args. For the host's page UI it implements set_page(n) / get_page() /
    get_pages() and triggers 'page_changed' {page}. And it REPORTS, with
    'preview_loaded' {state, pages, ...}:

        - when its content is on screen                       state 'loaded'
        - when it could not show its content                  state 'failed'
        - when it is showing a notice it will replace itself  state 'preparing'
          (and again when it has replaced it)

    Something is reported by the time the viewer is ready: its final state, or
    'preparing' when the content arrives later. A viewer whose work is
    asynchronous either awaits it in an async on_ready() - jqhtml holds 'ready'
    until that returns - or reports 'preparing' first. Document_Preview adds
    attachment_id and render_status to whatever the viewer sends, and reads a
    payload with no state as 'loaded'.

    A viewer that never reports does not leave a host waiting: when a dynamically
    instantiated viewer has reached 'ready' and said nothing, Document_Preview
    reports for it - state 'loaded', pages from get_pages() or 1. That is decided
    by the lifecycle, not by a clock. The cost of relying on it is accuracy: a
    viewer that fills itself in after 'ready' is reported 'loaded' early. A viewer
    whose lifecycle THROWS never becomes ready; that is an error in the console,
    and nothing is reported on its behalf.

SHOULD_SHOW_TEXT_PREVIEW
    A host that shows extracted text BESIDE a document (a Preview/Text switch, a
    two-column split) asks $attachment->should_show_text_preview(), never the extraction
    status. Three ways the answer is no: there is no extracted text (pending, FAILED or
    UNSUPPORTED); the preview ALREADY IS the text (a text/* file renders through
    Text_Viewer, so a pane beside it repeats every character); or the extraction is not
    legible to a human (a spreadsheet). The last two are mime globs in
    config('rsx.preview.text_preview_suppressed'); text/markdown is covered by the
    text/* glob there, so a markdown file recommends its rendered preview alone.

    It is returned by BOTH get_preview_info() and get_extracted_text() - the second so a
    caller already holding the text needs no second round trip - and it never gates the
    text itself, which is returned whatever the flag says.

DOCUMENT_TEXT_PREVIEW COMPONENT
    <Document_Text_Preview> renders the EXTRACTED TEXT of an attachment - the sibling
    of <Document_Preview>, which renders its picture. Neither knows about the other;
    a page may mount either, both, or neither.

        <Document_Text_Preview $attachment_id=this.data.doc.id />
        <Document_Text_Preview $attachment_id=42 $width=600 $height=400 />

    Args:
        $attachment_id  (required) File_Attachment_Model id. Throws if absent.
        $width/$height  (optional) fixed px; omitted -> fills the container (100%).

    Events OUT: 'preview_loaded' {attachment_id, state, length} - emitted for every
    state below and again after the swap out of the waiting one; see THE
    PREVIEW_LOADED EVENT. length is the text's length in characters, 0 when no text
    is showing. There are no public methods.

    STATES. Four, and the component paints exactly one of them:

        state        when                              renders
        ---------------------------------------------------------------------------
        (loading)    the first fetch has not answered  (Loading...)
        pending      no index row yet - extraction is  (Extracting Text...)
                     still queued
        available    text was extracted                the text, newlines preserved
        error /      the last extraction attempt       (Document Text Unavailable)
        unsupported  FAILED, a degraded upload, a file
                     type with no extractable text, an
                     extraction that yielded nothing,
                     or a caller the gate refused

    The three unavailable causes deliberately collapse into ONE notice: they are the
    same answer to a reader. An operator distinguishes them with
    rsx:search:reindex --status and rsx:documents:failed. The EVENT keeps one
    distinction the notice drops: an extraction that failed is 'failed', and text
    that simply does not exist is 'unavailable'.

    TYPOGRAPHY IS INHERITED, BY CONTRACT. document_text_preview.scss declares no
    font-family, font-size, color or line-height - only layout, scrolling and
    white-space:pre-wrap. A page that wants the text monospaced, smaller or muted
    says so on the element it mounts the component into.

    REALTIME. The component subscribes to its attachment in on_create() exactly as
    <Document_Preview> and <Attachment_Thumbnail> do, so when the background pass
    finishes and emits its frame the notice swaps to the text with no reload and no
    polling. On a realtime-disabled box "(Extracting Text...)" persists until the next
    navigation - there is deliberately no polling.

    ENDPOINT. File_Preview_Controller::get_extracted_text (#[Ajax_Endpoint]) returns
    {status: available|pending|error|unsupported, text: string|null} - the same
    vocabulary GET /api/v1/files/:key/text uses, so a page and an integration describe
    the same document the same way. It runs the CONTENT gate cascade
    (file.thumbnail.authorize THEN file.download.authorize), NOT the metadata gate
    get_preview_info runs: extracted text is often the whole document, so it is gated
    like the bytes. Both gates are MANDATORY: with no handler registered for either,
    every preview, rendition and extracted-text read throws naming the missing gate
    (rsx:man file_upload, SECURITY HOOKS). Text is returned uncapped up to config('rsx.search.max_text_bytes').

THE PREVIEW_LOADED EVENT
    Every preview widget - <Attachment_Thumbnail>, <Document_Preview> and each viewer
    it hosts, <Document_Text_Preview> - emits the jqhtml event 'preview_loaded' when
    what it depicts has been put on screen.

    EVERY ONE OF THEM ALWAYS EVENTUALLY EMITS IT, whatever it ended up showing. A
    picture that would not load, a generic type icon, a record that does not exist,
    a degraded upload, a waiting notice: each COUNTS as having rendered and each is
    reported. A host never has to guard against the event not coming, and never
    reaches into a widget's markup (its <img>, its canvas) to find out for itself.

        this.sid('thumb').on('preview_loaded', (component, data) => {
            if (data.state !== 'loaded') return;        // only the real picture
            this.measure(data.natural_width, data.natural_height);
        });

    THE NAME is not 'loaded' because 'loaded' - like 'rendered' - is a jqhtml
    lifecycle event the framework fires itself, with no payload, on every
    component. One name serves every widget.

    A LATE SUBSCRIBER IS STILL TOLD. jqhtml events are sticky: on() and once()
    registered after the event are called at once with the payload of the last
    emission. A picture served from cache has usually loaded before any host can
    subscribe; the host subscribes whenever it likes and is answered. There is no
    "already loaded?" fork to write.

    IT IS EMITTED AGAIN WHENEVER THE CONTENT CHANGES - the realtime swap from a
    placeholder to the real picture, a reload() after $attachment_id changed, a
    page change in a paged viewer. When a widget REPLACES what is on screen it
    first withdraws the stored emission, so a subscriber that arrives while the
    next content is still loading waits for that content's report and is never
    handed the previous one. attachment_id in the payload says which attachment a
    report describes.

    PAYLOAD. Every emission carries:

        attachment_id   int. The attachment the report describes.
        state           what is on screen - see the table.
        render_status   where the widget has one (Attachment_Thumbnail,
                        Document_Preview): the blob's
                        File_Storage_Model::RENDER_STATUS_* id, 'none' for a record
                        with no resident blob, 'unavailable' for no record. The
                        value Attachment_Thumbnail also writes to
                        data-render-status.

    plus the widget's own keys: Attachment_Thumbnail adds variant, natural_width,
    natural_height (rsx:man thumbnails); Document_Preview adds pages, width,
    height, ratio (DOCUMENT_PREVIEW COMPONENT above); Document_Text_Preview adds
    length.

    STATE. Four values, one vocabulary:

        loaded       The widget's final content for this attachment is on screen.
        preparing    A waiting notice or placeholder the widget will replace BY
                     ITSELF. 'preview_loaded' is emitted again when it does.
        failed       The content should have been shown and could not be.
        unavailable  There is nothing to show and nothing went wrong: no record
                     (deleted, or not visible to this user), or no content of
                     this kind.

    A host that only needs "has it resolved" ignores state. A host that needs the
    content checks state === 'loaded'. A host showing its own spinner clears it on
    anything but 'preparing'.

        widget / what is on screen                                    state
        ---------------------------------------------------------------------------
        Attachment_Thumbnail
          the picture has decoded - the raster, or the type icon of   loaded
            a file that has no raster
          the extension icon of a PENDING render has decoded          preparing
          the extension icon of a FAILED render has decoded           failed
          the <img> could not be loaded or decoded                    failed
          the empty placeholder of a record that cannot be read       unavailable

        Document_Preview
          a viewer's document, page, image, text or grid - the        loaded
            Icon_Viewer's icon and file name included
          "Preparing preview..." (PENDING, or FAILED with a retry     preparing
            under way)
          a viewer's own waiting notice - (Extracting Text...),       preparing
            (Preparing Preview...), a grid still loading
          "Preview could not be generated" (FAILED)                   failed
          a viewer that could not show its source - pdf.js could not  failed
            load or parse it, the image errored, the extraction or
            the markdown render failed
          the "Preview unavailable" card - a degraded upload, or a    unavailable
            record that cannot be read
          a text file with nothing extractable                        unavailable

        Document_Text_Preview
          the extracted text                                          loaded
          (Loading...) / (Extracting Text...)                         preparing
          (Document Text Unavailable) - the extraction FAILED         failed
          (Document Text Unavailable) - no record, a file type with   unavailable
            no text, or a document that contains none

    'loaded' on a thumbnail says the widget is showing its FINAL picture, which for
    a file type with no raster is that type's icon; whether a file has a picture of
    its own is the attachment's is_image / has_thumbnail(), not the event's.

    WHAT IS NOT COVERED. The guarantee is about every outcome a widget can DISPLAY.
    A fault that stops a component's lifecycle outright - the transport failing
    under <Attachment_Thumbnail>'s record fetch, a custom viewer that throws - is
    an error, reported the way every unhandled error is, and not a preview state.
    One viewer cannot see its own failure: Spreadsheet_Viewer shows its grid in a
    sandboxed iframe, which reports a load for whatever its request answered, so a
    rendition request that fails in transit is still reported 'loaded'.

SERVER SURFACES
    Every /_preview/ route is declared in BOTH route tables on one handler. A
    portal page's <Document_Preview> (and pdf.js inside it) requests them under
    the portal's own address through Rsx_Portal.internal_url(), so they run as
    PORTAL requests and the gates receive the portal user (rsx:man portal,
    INTERNAL ENDPOINTS). A Bearer key on a portal-realm route answers the API's
    404.

    GET /_preview/pdf/:key   (File_Preview_Controller::pdf_rendition)
        The PDF that pdf.js loads. DUAL authorization gate cascade - a rendition
        exposes the full document, so BOTH file.thumbnail.authorize AND
        file.download.authorize must return true (identical to inline()/download).
        Authenticates an Authorization: Bearer API key as well as a session
        cookie, so an integration can fetch a rendition without a browser.
        After auth, the document.preview_rendition chain may override. Framework
        default: SERVE-ONLY, never convert. A PDF blob is served as-is. A mime whose
        rsx.documents.renderers renderer produces a PDF, and is switched on, is
        served from tmp/renditions/{blob-hash}.pdf - the rendition the background
        worker
        produced, content-addressed so identical bytes convert once - but ONLY when the
        blob is RENDERED; otherwise it 404s with a body naming the render state (never
        render_error). Anything else is 415. Served inline; immutable with a one-year
        cache when the request's ?v= is the attachment's current content version, and
        no-store for a request with no v or a superseded one (rsx:man file_upload,
        FILE ACCESS). GET /_preview/sheet/:key, the workbook's HTML grid, follows the
        same rule.

        A RENDERED blob whose rendition file has been LRU-evicted re-queues itself and
        404s for this one request rather than showing an error over a cache eviction -
        the same self-heal the thumbnail path performs.

    POST get_extracted_text  (#[Ajax_Endpoint])
        The payload <Document_Text_Preview> reads: {status, text}. See
        DOCUMENT_TEXT_PREVIEW COMPONENT above for the vocabulary and the gate cascade.

    POST get_preview_info  (#[Ajax_Endpoint])
        Server-side viewer resolution consumed by <Document_Preview>: returns
        {viewer, mime, file_name, extension, preview_unavailable, render_status_id,
        render_retrying, urls:{rendition, inline, icon}}. render_status_id is the
        blob's File_Storage_Model::RENDER_STATUS_*, or null when there is no resident
        blob at all; urls.rendition is present ONLY when the endpoint would actually
        serve one.

        THE CALL IS A VIEW. Unless the caller passes attend: false, it first asks
        Document_Render_Service::attend_view() whether the preview is missing for a
        reason the worker could now remedy (an evicted rendition, a soft failure
        whose check now passes, a hard failure whose retry interval has passed) and
        sets that retry in motion; render_retrying is true when it did, and a
        FAILED render_status_id beside it is about to be attempted again. A refetch
        caused by a realtime frame passes attend: false - <Document_Preview> does -
        so a retry that fails again does not start the next. The view grants no
        attempt and runs nothing in the request (rsx:man documents, THE WORK
        QUEUE).
        urls.rendition and urls.inline are the model builders' URLs and carry the
        attachment's content version, so the payload DIFFERS after a relink or a
        re-render - which is what makes <Document_Preview>'s refresh() repaint, for a
        PDF and an image as much as for a converted document.
        Gated by file.thumbnail.authorize only (metadata, not full content). No config
        is exported to the client - resolution is server-side.

    GET /_preview/pdfjs.mjs, GET /_preview/pdf_worker.mjs
        Stream the pdf.js module + worker bytes from the committed system/node_modules
        (pdfjs-dist), text/javascript, one-year cache. pdf.js is NEVER bundled: the
        Pdf_Viewer lazy-loads it from these routes with ?v={build_key} on first use and
        memoizes it class-wide. The dynamic import is routed through
        new Function('u','return import(u)') so the iife bundler leaves the native
        import() untouched (a bare import() would be rewritten to require()).

    The rendition cache is LRU-evicted to config('rsx.preview.quota_max_bytes') by
    File_Rendition_Service::cleanup_renditions (every 30 minutes); each cache hit is
    touch()'d so hot renditions survive.

CONFIGURATION
    config/rsx.php -> 'search' (extraction / full-text):
        enabled                bool    Master switch (env SEARCH_ENABLED). Default true.
        extractor_version      int     Pipeline generation. Bump + reindex --below-version
                                       to re-extract older rows. Default 2 (bumped from 1
                                       for the spreadsheet/presentation extraction fix).
        extractors             array   fnmatch map: mime glob -> extractor class
                                       (simple, manifest-resolved), resolved by
                                       MIME MAP PRECEDENCE (rsx:man documents); no
                                       match -> UNSUPPORTED. Extended or overridden
                                       per type in rsx/resource/config/rsx.php
                                       (CUSTOM EXTRACTORS above). Ships:
                                         application/pdf              -> Pdftotext_Text_Extractor
                                         application/msword, ms-excel,
                                         ms-powerpoint, openxml*, opendocument*,
                                         application/rtf              -> Libreoffice_Text_Extractor
                                         workbook mimes               -> Spreadsheet_Text_Extractor
                                         text/*, application/csv,
                                         application/json             -> Plain_Text_Extractor
        pdftotext_binary_path  ?string poppler pdftotext path (env). null = auto-detect.
        max_text_bytes         int     Extracted text is capped at this many bytes.
                                       Over-cap extraction is TRUNCATED to the cap and
                                       RECORDED on the row (metadata truncated=true +
                                       original_bytes), never FAILED and never silently
                                       dropped - a partial index stays discoverable.
                                       Default 2 MB.

    config/rsx.php -> 'preview' (Document_Preview / rendition):
        viewers                array   fnmatch map: mime glob -> viewer component,
                                       resolved by MIME MAP PRECEDENCE (rsx:man
                                       documents); '*' -> Icon_Viewer is the
                                       fallback. Extended or overridden per type
                                       in the app config.
        (which types get a rendition, and how it is produced, is
        rsx.documents.renderers - rsx:man documents, RENDERERS)
        browser_inline         array   Mimes a BROWSER can display in a tab of its own
                                       given Content-Disposition: inline (fnmatch globs),
                                       read by File_Attachment_Model::can_open_inline().
                                       THE TEST IS THE BROWSER'S NATIVE ABILITY, NOT
                                       OURS: a .docx is previewable here (the worker
                                       converts it) and is deliberately absent, so this
                                       list and 'viewers' are expected to disagree. Nor
                                       can it be derived from file_type_id - text/*,
                                       Word and Excel are all DOCUMENT and disagree.
        text_preview_suppressed array  Mimes whose EXTRACTED TEXT is not worth showing
                                       beside their preview (fnmatch globs), read by
                                       File_Attachment_Model::should_show_text_preview().
                                       text/* is REDUNDANT (the preview IS the text) and
                                       a spreadsheet is NOT LEGIBLE (an undelimited run
                                       of cell values with no rows or headings).
                                       Extraction still runs for every one of these and
                                       the text stays searchable and is still returned:
                                       the flag is advice about display, never
                                       authorization.
        quota_max_bytes        int     LRU cap on tmp/renditions. Default 200 MB.

BINARY DEPENDENCIES
    The pipeline shells out to external binaries. Provision on Debian/Ubuntu:

        apt-get install -y --no-install-recommends \
            libreoffice poppler-utils fonts-liberation fonts-dejavu-core

    - poppler-utils (pdftotext) backs PDF text extraction.
    - headless LibreOffice (soffice) backs Office text extraction AND Office->PDF
      renditions AND Office thumbnails (one shared soffice slot pool).
    - fonts: without at least one general font family soffice substitutes poorly. Add
      fonts-noto-cjk etc. for non-Latin content.

    rsx:health verifies all of these (LibreOffice, poppler-utils, and the
    "Document Render Backlog" row - which replaced "Search Index Backlog", because
    rendition and extraction are one worker and one queue, so two probes would be two
    ways of saying the same thing). Run it as a container-readiness gate. See
    rsx:man health.

REINDEX COMMAND
    php artisan rsx:search:reindex <selector>   (exactly one selector; fails loud otherwise)

        --status               report index counts only (no re-queue): total blobs,
                               queued vs indexed, by-status breakdown, extractor-version
                               histogram, enabled flag, current version.
        --all                  re-queue every blob
        --failed               re-queue blobs whose last extraction FAILED
        --below-version=N      re-queue blobs indexed by a generation older than N
        --storage=ID           re-queue one blob by _file_storage id
        --attachment=ID        re-queue the blob backing one attachment
                               (materializes external bytes first)

    Re-queuing is uniform: it sets is_indexed = 0 on the resolved blobs, makes them
    due now with NO ATTEMPTS CHARGED, and dispatches
    Document_Render_Service::render_pending; the sweep/kick then re-extracts one blob
    at a time. A blob has one queue entry for everything it owes, so a re-queued
    blob whose render is FAILED has that render attempted again in the same passes.

    REINDEX IS THE TEXT HALF ONLY. --failed here means an EXTRACTION failure (a
    _search_indexes row with status FAILED). A RENDER failure - soffice could not
    convert the document - is a different thing on a different column, listed by
    php artisan rsx:documents:failed and re-queued with
    php artisan rsx:documents:rerender --failed. Both commands print the other's
    remedy beside their own table, so a wrong guess costs nothing. See rsx:man documents.

DEMO
    /dev/document_preview - a template SPA page that previews the seeded sample
    documents (a multi-page PDF and an Office doc) through <Document_Preview>,
    exercising pagination, and shows the same document's text through
    <Document_Text_Preview>. Its Reset Extraction / Extract Now buttons make the async
    extraction observable by hand: the notice reappears, then swaps back to the text
    over the realtime frame, with no reload. Run it with:

        php artisan rsx:debug /dev/document_preview --user=1

RSX VS LARAVEL
    Search:
        Laravel: install Scout + a driver, define searchable(), run a queue worker.
        RSX:     upload is auto-queued; search_text() returns a Builder; FULLTEXT is
                 built in on the dedup store.
    Preview:
        Laravel: wire a JS PDF library and a server raster route per format by hand.
        RSX:     <Document_Preview $attachment_id=...> resolves the viewer server-side;
                 pdf.js is lazy-served from node_modules, never bundled. The extracted
                 text is <Document_Text_Preview $attachment_id=...>, same one arg.
    Extension:
        Laravel: subclass drivers / swap service bindings.
        RSX:     one #[OnEvent] resolve handler per stage (extract / rendition /
                 thumbnail), first non-null wins.

TROUBLESHOOTING
    Text never appears for a document
        Check get_extraction_status(): null = still pending (is the worker running?
        rsx:health "Task Scheduler Liveness" and "Document Render Backlog";
        php artisan rsx:documents:status). FAILED = read the row's error
        (rsx:search:reindex --failed after fixing the binary). UNSUPPORTED = no
        extractor for that mime, LibreOffice disabled, or the document is
        password-protected/encrypted (the row's error names the reason - a reindex
        will not help, it is unextractable by design).

        Right after an upload, "pending" is the CORRECT answer, not a symptom: the
        whole pipeline is asynchronous now.

    The preview says "Preparing preview..." and stays there
        The blob is PENDING, or FAILED with a retry this view started. php artisan
        rsx:documents:status says whether anything is queued and when the sweeper
        next runs; if the count never falls, the worker is not running
        (rsx:task:process) or rsx.libreoffice.enabled is false. A FAILED document
        with no retry under way shows a failed state instead - the reason is in
        php artisan rsx:documents:failed.

    Text or a preview failed with "... is not installed or not executable" or "the
    source file is missing or unreadable"
        A soft failure - the box, not the document. No attempt was spent; fix what
        it names and the worker processes it at the next check (opening the
        preview checks at once). rsx:man documents, THE WORK QUEUE.

    Office docs extract/convert but PDFs do not (or vice versa)
        Different binaries: PDFs need poppler-utils (pdftotext); Office needs soffice.
        rsx:health reports each independently.

    Preview pane is blank / a PDF will not load
        Confirm /_preview/pdfjs.mjs returns 200 (pdfjs-dist installed under
        system/node_modules) and that the dual auth gates allow /_preview/pdf/:key.

    A document returns 415 from /_preview/pdf/:key
        No rsx.documents.renderers entry matches its pipeline mime, its renderer
        produces HTML (a workbook - /_preview/sheet/:key), or its renderer is
        switched off.

    A document returns 404 from /_preview/pdf/:key
        Not an error condition - the blob is not RENDERED yet (the body names the
        state). The viewer never requests the rendition in that state; a 404 here means
        something asked for it directly. php artisan rsx:documents:status.
