NAME
    LibreOffice Integration - headless soffice, invoked only by the render worker

SYNOPSIS
    Config:    config('rsx.libreoffice.*')
    Discovery: App\RSpade\Core\Files\Libreoffice::find_soffice()
    Callers:   App\RSpade\Core\Files\Document_Render_Service      (document -> PDF)
               App\RSpade\Core\Search\Libreoffice_Text_Extractor  (sheets/decks -> text)

DESCRIPTION
    Headless LibreOffice turns an Office document (Word/Excel/PowerPoint/OpenDocument)
    into something the rest of the framework can use: a PDF rendition, which feeds
    BOTH the Document_Preview viewer and the document's thumbnail, and - for
    spreadsheets and presentations - a flat-XML file the text extractor reads.

    SOFFICE IS INVOKED BY THE BACKGROUND WORKER AND BY NOTHING ELSE. A web request
    never converts a document. Document_Render_Service::render_pending is #[Exclusive],
    so at most one pass runs cluster-wide and its soffice calls are serialized by
    construction; the text extractor's own fods/fodp conversions run inside that same
    worker pass. See rsx:man documents for operating the pipeline and rsx:man thumbnails
    for the render state machine.

    THIS IS WHY THERE IS NO CONCURRENCY SECTION ANY MORE. Until 2026-08-22 three
    callers (a thumbnail renderer, the text extractor, and the preview controller)
    each shelled out to soffice from inside a web request, competing for a two-slot
    cluster semaphore, and a single Word document was converted THREE times for three
    artifacts of the same bytes. One worker replaced all three: one conversion, one
    caller, nothing left to bound. The semaphore, rsx.libreoffice.max_concurrent and
    rsx.libreoffice.slot_wait_timeout are GONE, as is Libreoffice_Thumbnail_Renderer.

    The integration is GENERIC and framework-level; nothing application-specific is
    involved.

HOW IT WORKS
    1. An attachment whose pipeline mime matches config('rsx.preview.convertible')
       flips its blob to PENDING on create and kicks the worker.
    2. The worker stages the extensionless, content-addressed blob under its
       representative extension (soffice detects the input format from the filename)
       inside a private per-invocation work dir, then runs:

           soffice -env:UserInstallation=file://<tmp>/profile --headless \
                   --convert-to pdf --outdir <tmp> <staged-source>

       The private user profile is what lets a fresh invocation never collide with a
       stale LibreOffice profile.
    3. The produced PDF is published ATOMICALLY into the rendition cache: copied to a
       temp file BESIDE tmp/renditions/{blob-hash}.pdf (same filesystem) and
       renamed over the destination. A half-written rendition is never observable.
    4. The blob settles RENDERED, its poisoned thumbnail cache entries are purged, and
       every attachment referencing it emits a realtime frame.
    5. The thumbnail pipeline later rasterizes page 1 of that PDF with Imagick, through
       the renderer registered for application/pdf - an ordinary PDF like any other.

    Text extraction for word-processing documents (doc/docx/odt/rtf) does NOT run
    soffice at all any more: it runs pdftotext over the rendition the same pass just
    produced. Spreadsheets and presentations keep their own soffice conversion (to
    fods/fodp), because the flat-XML route is the only one that reads every sheet and
    every slide - see rsx:man document_search.

    FAIL LOUD, RECORD, MOVE ON. __convert_to_pdf() throws on any failure (missing
    soffice, non-zero exit, no output, timeout). render_storage() catches it, records
    render_status_id = FAILED with the message in render_error, attempts the extraction
    anyway so the failure is visible to rsx:search:reindex --failed as well, notifies
    open pages, and continues to the next blob. FAILED IS TERMINAL - the sweeper never
    retries it; php artisan rsx:documents:rerender --failed is the operator action.

ENABLE / DISABLE
    config('rsx.libreoffice.enabled') is the master switch (env LIBREOFFICE_ENABLED,
    default true).

    - Enabled + conversion succeeds  -> rendition on disk, real document thumbnail,
                                        Document_Preview shows the document.
    - Enabled + conversion fails      -> FAILED recorded with its reason; the generic
                                        extension icon is served (uncacheable).
    - Disabled                        -> NO soffice call is ever made. Convertible
                                        documents STAY PENDING (they are not lost - the
                                        day it is switched back on the sweeper renders
                                        them), the rendition endpoint has nothing to
                                        serve, and thumbnails use the extension icon.
                                        Text extraction of PDFs and plain text keeps
                                        draining normally.

    Disable on nodes where LibreOffice is not installed:
        LIBREOFFICE_ENABLED=false   (in that node's .env)

TIMEOUT
    config('rsx.libreoffice.timeout') - default 120 seconds - is THE ONE SANCTIONED
    TIMEOUT in this subsystem, and the only one in the document pipeline. The
    justification is written out in full beside the key in config/rsx.php, because a
    sanctioned timeout that is not justified in place is not sanctioned. In brief:

    WHAT IT BOUNDS
        ONE external document-binary invocation made by the render worker: soffice (a
        rendition, or an fods/fodp text conversion) or pdftotext. It bounds the
        EXTERNAL BINARY - never any work of ours, and never the worker's own pass.

    WHY IT QUALIFIES
        These binaries do not merely run slowly on malformed input; they WEDGE - the
        process never returns and never will. The worker is single-threaded, so one
        wedged document would stop every later document in the queue forever. Expiry
        degrades to a WORKING OUTCOME: the blob is recorded FAILED with its reason, the
        extension icon is served, and the queue moves on.

    WHY 120
        The number does not separate "fast" from "slow"; it separates "still working"
        from "never coming back". A large, complex document on a loaded box legitimately
        takes well over a minute, so 120 sits far above any honest render, while a
        wedged soffice would sit there forever.

    WHY ONE KEY FOR BOTH BINARIES
        pdftotext is the same shape of risk with the same degradation. A second number
        would have to be argued separately and would drift; one key, one number, every
        site. (config('rsx.search.timeout') was that second number and is gone.)

    Do NOT lower this because renders "should be faster" - that will start failing
    legitimate renders.

THE DOCUMENT SANDBOX
    config('rsx.libreoffice.sandbox') - 'none' (default) or 'docker' (env
    LIBREOFFICE_SANDBOX). It decides whether soffice and pdftotext run on the host
    or inside a throwaway container, and it is the security posture for a site that
    accepts uploads from outside the organisation.

  WHY
    soffice and pdftotext are large C++ parsers of hostile input, and an uploaded
    document is input somebody else chose:

      - The import filters are a long-running source of memory-corruption CVEs. A
        crafted document is an exploit delivery mechanism, not merely a bad file.
      - A document can carry event and script hooks that a converter will honour.
      - A filter can be told to read a LOCAL FILE and embed it - the classic shape
        of "convert this and mail me back the PDF" exfiltration.
      - A document can reference resources the converter FETCHES OVER THE NETWORK,
        which aims the converter at whatever the box can reach internally.

    The render worker runs as a user that can read the application tree, its
    storage, and its credentials. Sandboxed, the converter can read one directory.

  WHAT THE CONTAINER GETS

        docker run --rm --name rsx-doc-<random> \
            --network none --read-only --cap-drop ALL \
            --security-opt no-new-privileges \
            --memory <sandbox_memory> --pids-limit <sandbox_pids> \
            --tmpfs /tmp --user <uid>:<gid> \
            -e HOME=<work_dir> -v <work_dir>:<work_dir> \
            --entrypoint '' <sandbox_image> <the ordinary argv>

      --network none          no linked resource is ever fetched, and nothing
                              internal is reachable from the parser.
      --read-only             the image's filesystem cannot be modified, so
                              nothing a document does can persist into the next
                              conversion.
      --cap-drop ALL          no capability is needed to convert a file.
      --security-opt
        no-new-privileges     a setuid binary inside the image cannot escalate.
      --memory / --pids-limit a malformed document that balloons or forks is
                              contained instead of taking the host down. The
                              memory cap is the one flag a daemon can refuse (a
                              host whose cgroup layout is in threaded mode
                              admits no memory controller); the seam probes for
                              that once per process and DROPS the cap rather
                              than stop converting, and the "Document Sandbox:
                              memory cap" health row reports the daemon's own
                              words. Every other flag is always applied.
      --tmpfs /tmp            scratch space that dies with the container.
      --user <uid>:<gid>      the worker's own identity, so the files written
                              into the work dir belong to the process that has to
                              read and delete them.
      -v <work_dir>:<work_dir>
                              THE ONLY MOUNT, at its own absolute path. Every path
                              in the argv - the staged input, the
                              -env:UserInstallation profile, the --outdir - is
                              therefore valid unchanged inside the container, so
                              one argv is correct in both modes. The blob is
                              COPIED into the work dir first: mounting the storage
                              tree into the sandbox would defeat the point of
                              having one.
      --entrypoint ''         the framework image's ENTRYPOINT brings a whole
                              environment up; cleared, the argv IS the process.

  ONE CONTAINER PER FILE, SEQUENTIAL, PRISTINE EACH TIME
    The render worker is #[Exclusive] and single-threaded, so conversions are
    serialized already; the sandbox adds one `docker run --rm` per file on top of
    that. Nothing survives a document: the next one gets a new process in a new
    filesystem.

    A LONG-LIVED PER-TENANT CONTAINER IS THE WRONG TRADE. It re-introduces exactly
    what the container is for - a process one document can leave modified for the
    next one - and it buys only container-start latency on a pipeline that is
    already asynchronous and whose unit of work is a multi-second conversion.

  DEPLOYMENT REQUIREMENT
    The user the render worker runs as must be able to reach a docker daemon:
    membership of the docker group, or rootless docker for that user. Nothing
    else is required of the host - in 'docker' mode the host needs no LibreOffice
    and no poppler-utils at all, because the binaries live in the image.

    The image (config('rsx.libreoffice.sandbox_image'), env
    LIBREOFFICE_SANDBOX_IMAGE) must carry soffice, pdftotext and fonts.

  THE CONVERTER IMAGE
    The default is the framework's own converter image,
    'rspade/rspade-docconvert:latest'. It is a bare ubuntu base carrying
    libreoffice, poppler-utils, fonts-liberation and fonts-dejavu-core - no PHP,
    no nginx, no redis, no supervisor, no entrypoint. That is the point: the
    image is the machine a hostile uploaded document is handed, so everything it
    carries is something a converter exploit could reach for, and an application
    runtime carries a great deal that converts nothing. It is a docconvert stage
    in the same Dockerfile as the application images and shares no layer with
    them.

    IT IS BUILT ON FIRST USE. Switching LIBREOFFICE_SANDBOX to 'docker' is a
    posture, not an installation step: the first sandboxed invocation on a host
    that does not have the image builds it (Document_Sandbox::ensure_image(),
    once per process, inside the asynchronous render worker) and then converts.
    Two ways to pay that cost deliberately instead:

        php artisan rsx:heal document-sandbox-image
        bash system/app/RSpade/resource/docker/build.sh docconvert

    AN OPERATOR'S OWN IMAGE IS NEVER BUILT. Point LIBREOFFICE_SANDBOX_IMAGE at an
    image of your own and it must carry soffice, pdftotext and fonts, and it is
    yours to distribute: the framework has no Dockerfile for it and nothing to
    guess from, so an absent one throws naming the image and `docker pull`, the
    health row FAILs rather than WARNs, and rsx:heal REFUSES. The framework
    builds exactly one image - rspade/rspade-docconvert, at whatever tag is
    configured - and nothing else.

  WHAT IS NOT COVERED
    PhpSpreadsheet. A workbook's HTML rendition (Spreadsheet_Rendition) and a
    workbook's text (Spreadsheet_Text_Extractor) are read IN-PROCESS by a PHP
    library - no binary is spawned, so there is no process to contain. Sandboxing
    that would mean sandboxing PHP itself.

  THE TIMEOUT PATH
    When the sanctioned bound expires, Symfony kills the process it started -
    which under the sandbox is the docker CLIENT, not the container. So every
    caller that enforces the bound also runs `docker kill` on the container it
    named (Document_Sandbox::container_name() / ::kill()). Without that, a wedged
    converter would keep running with the work dir still mounted.

  THE HEALTH ROWS
    rsx:health carries one "Document Sandbox" check in every mode:

      sandbox='none'    INFO in development (it is the default); WARN on a debug
                        or production box, naming LIBREOFFICE_SANDBOX=docker. It
                        is a WARN and not a FAIL because a site whose uploads all
                        come from inside the organisation is entitled to this
                        posture, and the exit code gates deploys.
      sandbox='docker'  FIVE rows - docker client, docker daemon, sandbox image,
                        sandbox run, memory cap. A failing link is a FAIL, because
                        a box configured to sandbox and unable to is a box that
                        renders nothing. The "sandbox run" row is the one that
                        proves the whole chain: it runs `soffice --version`
                        inside the configured image with the SAME hardening flags
                        a real conversion gets, and carries what the daemon said
                        when it could not.

                        THE IMAGE ROW SPLITS BY WHOSE IMAGE IT IS. An absent
                        FRAMEWORK converter image is a WARN: it is built on
                        demand, so the state resolves itself, but the first
                        document conversion on that box takes a minute or two
                        longer while the image builds - the row recommends
                        building it once with `rsx:heal document-sandbox-image`.
                        That heal ALWAYS rebuilds, present or not; docker's
                        layer cache makes a rebuild of an unchanged image a
                        matter of seconds, and it keeps the tagged image in step
                        with the checkout. An absent operator image is a FAIL
                        naming `docker pull`: nothing here will ever produce it.

    In 'docker' mode the "LibreOffice (soffice)" row reports the IMAGE, as an
    INFO - a sandboxed host is not supposed to carry soffice, and looking for a
    host binary there would FAIL a correctly configured site.

CONFIGURATION
    config/rsx.php -> 'libreoffice':

        enabled      bool    Master switch. Default true (env LIBREOFFICE_ENABLED).
        binary_path  ?string Absolute path to the soffice binary. Default null
                             (env LIBREOFFICE_BINARY_PATH) = auto-detect on PATH and
                             common install locations (/usr/bin/soffice,
                             /usr/local/bin/soffice, /opt/libreoffice/program/soffice).
        timeout      int     Per-invocation cap in seconds on the external binary.
                             Default 120. See TIMEOUT above.
        sandbox      string  'none' (default) or 'docker'. See THE DOCUMENT
                             SANDBOX above (env LIBREOFFICE_SANDBOX). Any other
                             value throws at first use.
        sandbox_image
                     string  The image a sandboxed conversion runs. Default
                             'rspade/rspade-docconvert:latest' - the framework's
                             own converter image, built on first use (env
                             LIBREOFFICE_SANDBOX_IMAGE). See THE CONVERTER IMAGE
                             above.
        sandbox_memory
                     string  Memory cap for a sandboxed conversion. Default '1g'.
        sandbox_pids int     Pid cap for a sandboxed conversion. Default 256.

    WHICH MIMES CONVERT is config('rsx.preview.convertible') - one list, read by the
    attachment (to decide whether a new upload owes a render) and by the worker. It is
    overridable in rsx/resource/config/rsx.php.

    Office mimes are NOT registered in config('rsx.thumbnails.renderers'), by design:
    a renderer entry would mean converting a document inside a web request.

INSTALLING LIBREOFFICE
    RSpade dev Docker images ship LibreOffice preinstalled with sensible defaults. To
    provision another environment on Debian/Ubuntu:

        apt-get install -y --no-install-recommends \
            libreoffice-writer libreoffice-calc libreoffice-impress libreoffice-core \
            ghostscript poppler-utils fonts-liberation fonts-dejavu-core

    Notes:
    - ghostscript is required for Imagick to rasterize the PDF rendition (and for
      direct PDF-attachment thumbnails via Imagick_Thumbnail_Renderer).
    - poppler-utils (pdftotext) is what extracts text from renditions and PDFs.
    - Install at least one general-purpose font family; without fonts, LibreOffice
      substitutes poorly. Add fonts-noto-cjk etc. for non-Latin content.
    - The process user must be able to write to the system temp dir.
    - Some base images disable PDF reads in ImageMagick policy.xml; allow "read" for
      the PDF coder if PDF thumbnails come out blank.

    rsx:health verifies soffice, poppler, the sandbox and the render backlog - run
    it as a container-readiness gate. A host that sandboxes needs none of the
    packages above: set LIBREOFFICE_SANDBOX=docker instead, and provision access to
    a docker daemon for the worker's user.

    See docs.dev/reference/docker_container_additions_7_2_2026.md for the full container
    provisioning writeup.

VERIFYING
        php artisan rsx:test --framework --group=documents

    Includes the real-soffice render path (it auto-skips when soffice is absent), the
    rendition-exists short-circuit, the terminal-FAILED behaviour and the thumbnail
    cache purge.
