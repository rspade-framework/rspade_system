NAME
    LibreOffice Integration - headless soffice, invoked only by the render worker

SYNOPSIS
    Config:    config('rsx.libreoffice.*')
    Discovery: App\RSpade\Core\Files\Libreoffice::find_soffice()
    Callers:   App\RSpade\Core\Files\Document_Render_Service      (document -> PDF)
               App\RSpade\Core\Search\Libreoffice_Text_Extractor  (sheets/decks -> text)

DESCRIPTION
    Headless LibreOffice turns an Office document (Word/Excel/PowerPoint/OpenDocument)
    into something the rest of the framework can use: a PDF rendition, which feeds
    BOTH the Document_Preview viewer and the document's thumbnail, and - for
    spreadsheets and presentations - a flat-XML file the text extractor reads.

    SOFFICE IS INVOKED BY THE BACKGROUND WORKER AND BY NOTHING ELSE. A web request
    never converts a document. Document_Render_Service::render_pending is #[Exclusive],
    so at most one pass runs cluster-wide and its soffice calls are serialized by
    construction; the text extractor's own fods/fodp conversions run inside that same
    worker pass. See rsx:man documents for operating the pipeline and rsx:man thumbnails
    for the render state machine.

    THIS IS WHY THERE IS NO CONCURRENCY SECTION ANY MORE. Until 2026-08-22 three
    callers (a thumbnail renderer, the text extractor, and the preview controller)
    each shelled out to soffice from inside a web request, competing for a two-slot
    cluster semaphore, and a single Word document was converted THREE times for three
    artifacts of the same bytes. One worker replaced all three: one conversion, one
    caller, nothing left to bound. The semaphore, rsx.libreoffice.max_concurrent and
    rsx.libreoffice.slot_wait_timeout are GONE, as is Libreoffice_Thumbnail_Renderer.

    The integration is GENERIC and framework-level; nothing application-specific is
    involved.

HOW IT WORKS
    1. An attachment whose pipeline mime matches config('rsx.preview.convertible')
       flips its blob to PENDING on create and kicks the worker.
    2. The worker stages the extensionless, content-addressed blob under its
       representative extension (soffice detects the input format from the filename)
       inside a private per-invocation work dir, then runs:

           soffice -env:UserInstallation=file://<tmp>/profile --headless \
                   --convert-to pdf --outdir <tmp> <staged-source>

       The private user profile is what lets a fresh invocation never collide with a
       stale LibreOffice profile.
    3. The produced PDF is published ATOMICALLY into the rendition cache: copied to a
       temp file BESIDE storage/rsx-renditions/{blob-hash}.pdf (same filesystem) and
       renamed over the destination. A half-written rendition is never observable.
    4. The blob settles RENDERED, its poisoned thumbnail cache entries are purged, and
       every attachment referencing it emits a realtime frame.
    5. The thumbnail pipeline later rasterizes page 1 of that PDF with Imagick, through
       the renderer registered for application/pdf - an ordinary PDF like any other.

    Text extraction for word-processing documents (doc/docx/odt/rtf) does NOT run
    soffice at all any more: it runs pdftotext over the rendition the same pass just
    produced. Spreadsheets and presentations keep their own soffice conversion (to
    fods/fodp), because the flat-XML route is the only one that reads every sheet and
    every slide - see rsx:man document_search.

    FAIL LOUD, RECORD, MOVE ON. __convert_to_pdf() throws on any failure (missing
    soffice, non-zero exit, no output, timeout). render_storage() catches it, records
    render_status_id = FAILED with the message in render_error, attempts the extraction
    anyway so the failure is visible to rsx:search:reindex --failed as well, notifies
    open pages, and continues to the next blob. FAILED IS TERMINAL - the sweeper never
    retries it; php artisan rsx:documents:rerender --failed is the operator action.

ENABLE / DISABLE
    config('rsx.libreoffice.enabled') is the master switch (env LIBREOFFICE_ENABLED,
    default true).

    - Enabled + conversion succeeds  -> rendition on disk, real document thumbnail,
                                        Document_Preview shows the document.
    - Enabled + conversion fails      -> FAILED recorded with its reason; the generic
                                        extension icon is served (uncacheable).
    - Disabled                        -> NO soffice call is ever made. Convertible
                                        documents STAY PENDING (they are not lost - the
                                        day it is switched back on the sweeper renders
                                        them), the rendition endpoint has nothing to
                                        serve, and thumbnails use the extension icon.
                                        Text extraction of PDFs and plain text keeps
                                        draining normally.

    Disable on nodes where LibreOffice is not installed:
        LIBREOFFICE_ENABLED=false   (in that node's .env)

TIMEOUT
    config('rsx.libreoffice.timeout') - default 120 seconds - is THE ONE SANCTIONED
    TIMEOUT in this subsystem, and the only one in the document pipeline. The
    justification is written out in full beside the key in config/rsx.php, because a
    sanctioned timeout that is not justified in place is not sanctioned. In brief:

    WHAT IT BOUNDS
        ONE external document-binary invocation made by the render worker: soffice (a
        rendition, or an fods/fodp text conversion) or pdftotext. It bounds the
        EXTERNAL BINARY - never any work of ours, and never the worker's own pass.

    WHY IT QUALIFIES
        These binaries do not merely run slowly on malformed input; they WEDGE - the
        process never returns and never will. The worker is single-threaded, so one
        wedged document would stop every later document in the queue forever. Expiry
        degrades to a WORKING OUTCOME: the blob is recorded FAILED with its reason, the
        extension icon is served, and the queue moves on.

    WHY 120
        The number does not separate "fast" from "slow"; it separates "still working"
        from "never coming back". A large, complex document on a loaded box legitimately
        takes well over a minute, so 120 sits far above any honest render, while a
        wedged soffice would sit there forever.

    WHY ONE KEY FOR BOTH BINARIES
        pdftotext is the same shape of risk with the same degradation. A second number
        would have to be argued separately and would drift; one key, one number, every
        site. (config('rsx.search.timeout') was that second number and is gone.)

    Do NOT lower this because renders "should be faster" - that will start failing
    legitimate renders.

CONFIGURATION
    config/rsx.php -> 'libreoffice':

        enabled      bool    Master switch. Default true (env LIBREOFFICE_ENABLED).
        binary_path  ?string Absolute path to the soffice binary. Default null
                             (env LIBREOFFICE_BINARY_PATH) = auto-detect on PATH and
                             common install locations (/usr/bin/soffice,
                             /usr/local/bin/soffice, /opt/libreoffice/program/soffice).
        timeout      int     Per-invocation cap in seconds on the external binary.
                             Default 120. See TIMEOUT above.

    WHICH MIMES CONVERT is config('rsx.preview.convertible') - one list, read by the
    attachment (to decide whether a new upload owes a render) and by the worker. It is
    overridable in rsx/resource/config/rsx.php.

    Office mimes are NOT registered in config('rsx.thumbnails.renderers'), by design:
    a renderer entry would mean converting a document inside a web request.

INSTALLING LIBREOFFICE
    RSpade dev Docker images ship LibreOffice preinstalled with sensible defaults. To
    provision another environment on Debian/Ubuntu:

        apt-get install -y --no-install-recommends \
            libreoffice-writer libreoffice-calc libreoffice-impress libreoffice-core \
            ghostscript poppler-utils fonts-liberation fonts-dejavu-core

    Notes:
    - ghostscript is required for Imagick to rasterize the PDF rendition (and for
      direct PDF-attachment thumbnails via Imagick_Thumbnail_Renderer).
    - poppler-utils (pdftotext) is what extracts text from renditions and PDFs.
    - Install at least one general-purpose font family; without fonts, LibreOffice
      substitutes poorly. Add fonts-noto-cjk etc. for non-Latin content.
    - The process user must be able to write to the system temp dir.
    - Some base images disable PDF reads in ImageMagick policy.xml; allow "read" for
      the PDF coder if PDF thumbnails come out blank.

    rsx:health verifies soffice, poppler and the render backlog - run it as a
    container-readiness gate.

    See docs.dev/reference/docker_container_additions_7_2_2026.md for the full container
    provisioning writeup.

VERIFYING
        php artisan rsx:test --framework --group=documents

    Includes the real-soffice render path (it auto-skips when soffice is absent), the
    rendition-exists short-circuit, the terminal-FAILED behaviour and the thumbnail
    cache purge.
