CONFIG_RSX(1)                  RSpade Manual                  CONFIG_RSX(1)

NAME
    config/rsx.php - RSX framework configuration file

SYNOPSIS
    config('rsx.mode')                       # read one key
    config('rsx.tasks.global_max_workers')   # read a nested key
    config('rsx.portal', [])                 # read a whole section

DESCRIPTION
    RSX configuration lives in TWO files that are deep-merged at boot:

        system/config/rsx.php        Framework defaults (this page)
        rsx/resource/config/rsx.php  Application overrides

    system/config/rsx.php ships with the framework and holds the
    operational defaults every RSpade install needs. An application
    customizes behavior in rsx/resource/config/rsx.php; it never edits
    the framework file. Both are plain PHP files returning one array, read
    through Laravel's config() helper under the 'rsx' namespace.

    Unlike Laravel, which spreads settings across many config/*.php files
    and wires features through service providers, RSX keeps its framework
    settings in this single file, discovers code through the manifest, and
    exposes overrides through the one user file above. Prefer config() over
    env(): env() is only for deployment-specific secrets/hostnames
    (DB_PASSWORD, APP_URL, ...); application behavior belongs in config.

TWO-TIER MERGE
    Rsx_Framework_Provider::register() loads system/config/rsx.php as the
    base, then deep-merges rsx/resource/config/rsx.php over it via
    array_merge_deep():

    - Scalar values     User value REPLACES the framework value.
    - Array values      Combined (framework entries + user entries).
    - Nested arrays     Recursively merged.

    So a user 'bundle_aliases' block ADDS to the framework aliases rather
    than replacing them, while a user 'mode' scalar overrides outright.
    The user file is optional; absent, pure framework defaults apply.

    A third, test-runner-only layer merges last: if the RSX_ADDITIONAL_CONFIG
    env var points at a PHP config file, its array is merged on top of the
    user config (used by Rsx_Test_Command to inject per-run overrides).

    App-developer detail: rsx/resource/config/CLAUDE.md.

    Keys that are application PREFERENCES rather than framework
    requirements were moved OUT of the framework file into user config
    (console_debug outputs/filters, log_browser_errors, response
    defaults, development.auto_rename_files, and more). The
    framework file only carries what the framework itself must have to run.

APPLICATION MODE
    'mode' => env('RSX_MODE', 'development')

    Authoritative source of truth for application mode: development, debug,
    or production. Drives minification, sourcemaps, console_debug stripping,
    and sealed-build behavior. See: php artisan rsx:man app_mode

MANIFEST AND BUNDLE PIPELINE
    'manifest_modules'   Modules run DURING manifest scanning to process
                         file types (Blade, SCSS). PHP and JS are handled
                         directly in Manifest.php.
    'manifest_support'   Modules run AFTER the manifest is built to add
                         metadata needing the full index (Route, Portal
                         route/SPA, Model, Jqhtml, SPA, Api_Endpoint).
    'integrations'       Integration service providers ('providers') plus
                         per-integration config (e.g. jqhtml compiler
                         cache/ttl/source_maps).
    'bundle_processors'  Processors that transform files during bundle
                         compilation (Scss, Jqhtml).
    'required_bundles'   Bundles prepended to every bundle's include list.
                         Default: ['jquery', 'lodash', 'core', 'jqhtml'].
    'bundle_aliases'     Short name => Bundle class map for use in include
                         arrays. Framework: core, jquery, lodash,
                         bootstrap5, jqhtml.

    'manifest' => [
        'scan_directories' => [...],   # dirs scanned for RSX code
        'excluded_files' => [...],     # filenames skipped anywhere
        'excluded_dirs' => [...],      # path segments skipped in scans
    ]

    scan_directories     Base dirs indexed (rsx, app/RSpade/Core,
                         Integrations, Bundles, ...). Relative to base_path().
    excluded_files       CLAUDE.md, .placeholder, .DS_Store, .gitkeep, ...
    excluded_dirs        vendor, node_modules, storage, .git, public,
                         resource, Core/Manifest, playwright, _archive.

    NOTE: minification and sourcemaps are decided by application MODE
    (Manifest::_should_minify() etc.), NOT by any config key here.

HTTP MIDDLEWARE
    'middleware' => [
        'global'  => [],
        'web'     => [],
        'api'     => [],
        'aliases' => [],
    ]

    The sanctioned seam for an application's own HTTP middleware.
    system/app/Http/Kernel.php is a FRAMEWORK-OWNED file - every framework
    update overwrites it - ALL of system/ is framework property - so it carries
    a local edit - so an app never registers middleware by editing the
    kernel. It declares it here and the kernel folds it in at bootstrap.

    global               Appended to the global stack (runs on every request).
    <group>              Appended to that middleware GROUP. The key must name
                         a group the kernel declares ('web', 'api'); anything
                         else is a loud error, not a new group.
    aliases              alias => class map, merged beside the framework's
                         route-middleware aliases.

    APPEND-ONLY, deliberately. Declared middleware runs AFTER the framework
    stack, at the end of the group, or beside the existing aliases. There is
    no spelling that reorders or removes framework middleware; needing that
    is a framework change request, not a config key. (Same philosophy as
    csp.additional_sources: widen, never narrow.)

    Validation is loud, at bootstrap, naming what is wrong:
    - a class that does not exist                RuntimeException, class named
    - an unknown group key                       RuntimeException, valid keys listed
    - an alias already bound to another class    RuntimeException, BOTH classes named
    Declaring a class or alias that is already present is a silent no-op, so
    the block is idempotent.

    A ':parameters' suffix is honored (Throttle::class.':api'); the class part
    is what gets existence-checked.

    The framework declares none - the block ships empty.

TURNSTILE
    'turnstile' => [
        'enabled'    => env('TURNSTILE_ENABLED', false),
        'site_key'   => env('TURNSTILE_SITE_KEY'),    # public
        'secret_key' => env('TURNSTILE_SECRET_KEY'),  # server-only
        'verify_timeout_seconds' => 30,
    ]

    Cloudflare Turnstile human verification. enabled is the ONLY input
    that decides whether the feature is active - application mode has no
    bearing on it, which is what lets an endpoint call
    Rsx_Turnstile::validate() unconditionally.

    site_key is PUBLIC and ships to the browser as
    window.rsxapp.turnstile, but only when enabled; secret_key is the
    siteverify credential and is never exported. Enabling with either key
    empty throws (a half-configured install is a deployment fault, not a
    form error).

    verify_timeout_seconds bounds the outbound siteverify call. A
    SANCTIONED timeout, owner-approved 2026-08-12: expiry degrades to FAIL
    CLOSED (rejected, user retries), never to an accepted-without-
    verification pass. See: php artisan rsx:man turnstile

TWO-FACTOR AUTHENTICATION
    'two_factor' => [
        'issuer' => null,
        'challenge_window_minutes' => 10,
    ]

    Second factors (TOTP, passkeys, recovery codes). THERE IS NO ENABLE
    SWITCH, deliberately: 2FA is per identity - an identity either holds
    a confirmed credential or it does not - and a framework-wide flag
    would have to decide what happens to every account that has not
    enrolled yet, which is a policy only an application can hold.

    issuer is the label an authenticator app files the account under.
    null DERIVES it from Rsx::get_hostname(), which is what the user
    typed to get here and is recognisable in a list of twenty accounts
    in a way a product name may not be. A colon is stripped (the
    otpauth:// Key URI Format uses one to separate issuer from account).

    challenge_window_minutes is a SECURITY WINDOW, not an operation
    timeout: how long a passed-password-awaiting-second-factor state
    stays redeemable, and how long an in-flight WebAuthn ceremony or a
    parked enrollment seed stays satisfiable. It bounds no work, and
    expiry degrades to a working outcome ("sign in again"). Must be at
    least 1 - anything lower calls shouldnt_happen() rather than minting
    a window that is already closed. See: php artisan rsx:man two_factor

FEDERATED SIGN-IN (SSO)
    'sso' => [
        'providers' => [
            'google'    => ['enabled' => env('SSO_GOOGLE_ENABLED', false),
                            'client_id' => ..., 'client_secret' => ...],
            'microsoft' => [... , 'tenant' => env('SSO_MICROSOFT_TENANT', 'common')],
            'facebook'  => [...],
            'apple'     => [... , 'team_id', 'key_id', 'private_key'],
            'x'         => [...],
        ],
        'custom' => [],
        'skip_two_factor' => false,
        'pending_window_minutes' => 10,
    ]

    "Continue with Google/Microsoft/Facebook/Apple/X". ACTIVITY IS
    CONFIGURED, NOT DERIVED: a provider is live because its own enabled
    flag is true and for no other reason - mode, hostname and APP_URL
    have no bearing. There is no global enable switch. A provider
    enabled with a missing credential THROWS, naming the literal .env
    keys, rather than rendering a button that leads to somebody else's
    error page (the turnstile posture).

    Apple takes FOUR credentials because it has no static client secret:
    the secret is an ES256 JWT minted offline per token exchange from
    team_id/key_id/private_key (a path to the .p8, or the PEM itself).
    microsoft.tenant decides WHO may sign in ('common' / 'organizations'
    / 'consumers' / a tenant GUID) and is that provider's only real
    access control.

    custom is the extension seam: install a socialiteproviders adapter
    at the app layer and name its provider class here - no listener, no
    service provider. Every key in the entry that is not framework
    vocabulary is passed through to the adapter.

    skip_two_factor false means a provider sign-in STILL FACES this
    application's own second factor, which is the safe posture; true is
    for an IdP that is already the organization's MFA authority.

    pending_window_minutes is a SECURITY WINDOW, not an operation
    timeout, and the exact analogue of two_factor.challenge_window_
    minutes: how long an in-flight ceremony and a proven-but-unconnected
    provider identity stay redeemable. It bounds no work and expiry
    degrades to a working outcome ("That sign-in took too long"). Must
    be at least 1. See: php artisan rsx:man sso

CONTENT SECURITY POLICY
    'csp' => [
        'enabled'            => true,
        'additional_sources' => [],
    ]

    Every dispatched HTML page carries a composed per-realm policy, and it
    ALWAYS ENFORCES: the header is Content-Security-Policy and an undeclared
    resource is a blocked resource. Every refusal is POSTed to /_csp-report and
    appended to storage/logs/csp_violations.log, which is the triage tool.
    enabled false emits no header anywhere - an emergency kill-switch that
    deletes the protection, not a quiet observe mode.

    additional_sources (directive => [sources]) is merged WIDEN-ONLY and exists
    ONLY for TRANSITIVE externals: origins a declared script goes on to fetch
    by itself, which no declaration can enumerate. A resource the page loads
    directly belongs in a *.externals.php declaration, from which the whitelist
    derives automatically. object-src is refused outright (it is 'none'
    hardening, and appending would loosen it). Downstream config deep-merges
    additively, so an app's array widens the framework's.

    See: php artisan rsx:man csp
    See: php artisan rsx:man external_resources

CDN EXTERNALS
    'cdn_externals' => [
        'user_agent' => 'Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 ...',
    ]

    Every remote asset the application serves is mirrored to a FILE in
    rsx/resource/.cdn-cache/ (git-tracked) and served from /_vendor/ - one code
    path in every mode, so a development page and a sealed build load
    byte-identical assets and the CSP has no external origin to whitelist.

    user_agent is the User-Agent every mirror download sends - curl in Cdn_Cache
    and node in the CSS localizer alike. It spells a MODERN BROWSER on purpose:
    Google Fonts and CDNs like it content-negotiate on this header, serving a
    modern agent woff2 plus per-script unicode-range subsets and anything else
    one fat legacy TTF. What we mirror is what the browser will be handed, so we
    must ask the way it asks. Empty throws.

    Changing it changes what a URL mirrors, but does NOT invalidate anything: the
    store is keyed by URL, so an existing file is never re-fetched. Run
    php artisan rsx:cdn_externals:refresh to re-fetch under the new agent.

    See: php artisan rsx:man external_resources

ANALYTICS (template app)
    'analytics' => [
        'measurement_id' => env('GOOGLE_ANALYTICS_ID', ''),
    ]

    Lives in rsx/resource/config/rsx.php, not the framework file - it belongs
    to the template app's worked example (rsx/lib/analytics/). A GA4 id
    ('G-XXXXXXXXXX'); EMPTY MEANS OFF, which is how the template ships:
    nothing is fetched. Set it and the staff app loads gtag.js lazily through

LOG ROTATION
    'logging' => [
        'rotation' => [
            'enabled' => env('LOGROTATE_ENABLED', false),
            'days_uncompressed' => env('LOGROTATE_DAYS_UNCOMPRESSED', 3),
            'days_retention' => env('LOGROTATE_DAYS_RETENTION', 21),

    RSpade rotates storage/logs itself; no OS logrotate is assumed anywhere.

    'libreoffice' => [
        'enabled' => env('LIBREOFFICE_ENABLED', true),
        'binary_path' => env('LIBREOFFICE_BINARY_PATH', null),  # null = autodetect
        'timeout' => 120,             # THE one sanctioned timeout (see below)
    ]

    Headless LibreOffice, invoked ONLY by Document_Render_Service's background
    worker - never inside a web request. Off, or a failed conversion, degrades
    to the generic extension icon.

    timeout is a SANCTIONED TIMEOUT (owner ruling 2026-08-22), justified in full
    beside the key in config/rsx.php: it bounds ONE external document-binary
    invocation (soffice or pdftotext), which WEDGES rather than merely running
    slowly, and expiry degrades to a working outcome (FAILED + extension icon).
    One key covers both binaries. Do not lower it.

    REMOVED 2026-08-22 - delete any override you carry: max_concurrent and
    slot_wait_timeout. One #[Exclusive] worker is now the only caller of soffice,
    so there is no pool to size and no slot to wait for.
    See: php artisan rsx:man libreoffice

LOCKS
    'locks' => [
        'server_host' => env('LOCK_SERVER_HOST', '127.0.0.1'),
        'server_port' => env('LOCK_SERVER_PORT', 6210),
        'connect_retries' => 3,
        'connect_retry_delay_ms' => 1000,
    ]

    Where PHP dials the rsx-lockd daemon, which serves every WEB-CLUSTER
    lock. System locks are flock() on this box and are not configured here.

    server_host/server_port are the CONNECT side and must agree with the
    daemon's own listen side in system/bin/rsx-lockd/lockd.conf (or the
    project-root lockd.conf that overrides it). The Node daemon reads that
    JSON file directly and has no access to Laravel's config, so the two
    are kept in sync BY HAND. They are legitimately different VALUES - the
    daemon binds 0.0.0.0:6210, PHP dials 127.0.0.1:6210 - so change the
    PORT on both sides together.

    connect_retries/connect_retry_delay_ms are plain literals, not env():
    the common failure is a daemon mid-supervisor-restart, which is over in
    about a second. A rejected hello is a wrong APP_KEY and is never
    retried. There is no lock TIMEOUT key - a lock wait defaults to forever
    and is a per-call argument. See: php artisan rsx:man locks

REALTIME
    'realtime' => [
        'enabled' => env('REALTIME_ENABLED', false),
        'ws_port' => env('REALTIME_WS_PORT', 6200),
        'load_gate_timeout_ms' => 1500,
        'stale_reload_after_ms' => 3600000,
    ]

    WebSocket notification system. ws_port is ALSO read straight from .env
    by the Node relay (no Laravel config cache) - keep them in sync.
    load_gate_timeout_ms caps how long a component's first load waits for
    its subscription. stale_reload_after_ms is how long a tab may be
    disconnected or suspended before a successful reconnect forces a full
    page reload (resync fixes stale data, not a stale JS bundle); 0
    disables it.

    Also read from .env by the Node relay only: REALTIME_PHP_ORIGIN
    (default http://127.0.0.1) - where the relay reaches PHP to report
    newly-live subscriptions. A deployment fact, like the FPC proxy's
    backend host. See: php artisan rsx:man realtime

MAIL AND SMS
    'mail' => [
        # aiosmtpd | live | suppressed | disabled. Anything else THROWS.
        #   aiosmtpd   the development catcher on 127.0.0.1:1025 (THE DEFAULT); the
        #              whole 'transport' block below is IGNORED, and the catcher's
        #              SMTP greeting must say 'aiosmtpd'
        #   live       real delivery through 'transport'; the .dev.-hostname
        #              recipient gate applies in THIS MODE ONLY
        #   suppressed built and recorded, handed to nobody
        #   disabled   the queue is FROZEN - the drain returns, rows stay Pending
        'delivery' => env('MAIL_DELIVERY', 'aiosmtpd'),
        # READ IN 'live' MODE ONLY.
        'transport' => [
            'driver' => env('MAIL_TRANSPORT', 'smtp'),     # smtp | sendmail
            'host' => env('MAIL_HOST', '127.0.0.1'),
            'port' => (int) env('MAIL_PORT', 1025),
            'encryption' => env('MAIL_ENCRYPTION', ''),    # '' | tls | ssl
            'username' => env('MAIL_USERNAME', ''),
            'password' => env('MAIL_PASSWORD', ''),
            'sendmail_path' => '/usr/sbin/sendmail -bs -i',
        ],
        'from_address' => env('MAIL_FROM_ADDRESS', 'noreply@example.com'),
        'from_name' => env('MAIL_FROM_NAME', ''),          # '' = rsx.name
        'retry' => ['attempts' => 3, 'delay_minutes' => 3],
        'retention_days' => 30,
        # QUEUE HYGIENE, NOT A TIMEOUT. Guards against one configuration failure:
        # the queue silently stops working for a month, and on repair the drain
        # floods a month of stale, irrelevant, unretractable notices. The drain
        # refuses to send anything due more than this many days ago and marks the
        # row FAILED naming `rsx:mail:resend <id>` - the decision to send old mail
        # belongs to a human. Due date is COALESCE(next_attempt_at, created_at), so
        # a future send_at() is never born stale. Never runs in 'disabled'. email(7).
        'stale_after_days' => 2,
        'unsubscribe_secret' => null,   # null = derived from app.key
        'branding' => ['logo_url' => null, 'footer_text' => null],
        'dev_site' => [
            'catchall_address' => env('EMAIL_DEV_CATCHALL_ADDRESS', ''),
            'address_whitelist' => env('EMAIL_DEV_EMAIL_ADDRESS_WHITELIST', ''),
            'domain_whitelist' => env('EMAIL_DEV_EMAIL_DOMAIN_WHITELIST', ''),
        ],
        'catcher_maildir' => storage_path('mail-catcher'),
        'dkim_selector' => null,        # set = rsx:health looks up the DKIM TXT
    ]

    TWO INDEPENDENT SAFETY LAYERS, do not conflate them.

    'delivery' is the master switch and is CONFIGURED, not derived, with FOUR
    values (an unrecognised one throws). 'aiosmtpd' - the shipped default -
    hands each row to the development catcher on this box and ignores the
    'transport' block entirely; 'live' hands it to the configured transport;
    'suppressed' renders and records it without sending; 'disabled' freezes
    the queue so the drain does nothing and rows stay Pending. So a fresh
    install delivers into a local Maildir and nothing leaves the box.

    'dev_site' is the second layer, keyed on the HOSTNAME (Rsx::is_dev_site()
    - the host contains '.dev.'), and it applies in 'live' MODE ONLY.
    Each recipient is checked against the
    address whitelist, then the domain whitelist, then redirected to the
    catchall. No match and no catchall means the address is not deliverable
    from this host and the row is recorded SUPPRESSED.

    The dev_site layer does NOT engage in any other mode, because no other
    mode can reach a real person: 'aiosmtpd' files every message in a Maildir
    here, 'suppressed' never opens a transport, 'disabled' never drains.
    Gating there would record every message SUPPRESSED on a fresh install.

    'retry' is the SMTP SERVER-ERROR policy only: the server answered with an
    error for that one message, so it retries on its own clock and FAILs at
    the attempt cap with the server's reply recorded. A connection-level
    failure is not this - the runner reconnects once and then dies loud,
    leaving every row PENDING for the next sweep.

    See: php artisan rsx:man email

    'sms' => [

USER CONFIG KEYS (rsx/resource/config/rsx.php)
    The application override file carries app identity and preference keys
    that have no framework default (plus overrides of any framework key
    above). These are application-owned, documented here for orientation:

    name, description        Application identity used in UI/layouts.
    default_user             Dev auto-fill login (email/password).
    js_model_base_class      Custom JS base class for generated model stubs.
    console_debug            outputs, filter_mode, whitelist, blacklist,
                             specific_channel, include_*, enable_get_trace.
    log_browser_errors       Send browser JS errors to the Laravel log.
    response                 default_view, error_views, cors.
    notifications            default_expiry_days.
    auth                     signup_mode, verification_required,
                             invite_expiration_days (template-app).

CONFIG VS ENVIRONMENT
    Config files (version-controlled)   Application behavior: worker counts,
                                        thumbnail presets, retention days,
                                        viewer registries.
    Environment (.env, not committed)   Deployment-specific values: secrets,
                                        hostnames, feature toggles per host
                                        (DB_PASSWORD, APP_URL, REALTIME_*).

    Many keys wrap env() so a single value can be tuned per host, but the
    RULE stands: reach for env() only for deployment-specific values;
    everything else belongs in config.

RSX VS LARAVEL
    Laravel spreads configuration across many config/*.php files and wires
    features through service providers published per package. RSX keeps its
    framework settings in system/config/rsx.php, discovers code through the
    manifest, and offers exactly one override file
    (rsx/resource/config/rsx.php) deep-merged at boot. Framework defaults
    stay separate from application overrides so a framework pull never
    stomps app settings, and an app never edits framework files.

TROUBLESHOOTING
    An override is not taking effect
        Confirm the key is under the 'rsx' namespace and the nesting path
        matches exactly. Remember scalars replace but arrays MERGE - a user
        array ADDS to framework entries rather than replacing them.

    A value looks wrong at runtime
        The effective value is the MERGED result. Read it with
        config('rsx.<path>'); do not assume the framework default applies
        if the user file (or RSX_ADDITIONAL_CONFIG during a test run) sets
        the same key.

    An env() override does nothing
        The key may not read env() at all (many are plain literals). Check
        the actual default in system/config/rsx.php before setting a var.
