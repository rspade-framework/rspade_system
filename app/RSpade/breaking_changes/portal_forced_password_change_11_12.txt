A FLAGGED PORTAL USER SETS A NEW PASSWORD AT SIGN-IN (THE TEMPLATE'S PORTAL ADOPTS THE FORCED CHANGE)
Date: 2026-11-12

IF YOU DO NOTHING: a portal user flagged password_reset_required (by rsx:users:force_password_reset --portal-user=<id>, or by require_password_reset() on a Portal_User_Model) is turned away at your portal sign-in with "use Forgot your password?" and must complete an emailed reset; the framework's set-a-new-password-at-sign-in step (Portal_Auth::begin_forced_password_change()) is never reached.

SUMMARY
    Category 3 (a framework capability the template's portal now uses, with
    screens to port). Affects every application with a client portal built
    from the template.

THE CHANGE
    The template's portal sign-in, like the staff one, parks a flagged
    identity whose password matched (Portal_Auth::begin_forced_password_change())
    and shows "Choose a new password" at /login/new-password; completing it
    (Portal_Auth::complete_forced_password_change(), cause forced_change)
    continues the ordinary sign-in - a second step if owed, then
    Portal_Login_Controller::complete_sign_in(). Reference:
    system/app/RSpade/resource/reference_app/portal/auth/.

ACTION REQUIRED
    1. In your portal login controller's password branch, catch
       Auth_Password_Reset_Required_Exception: run your account rules
       (can_login()) on $e->identity, call
       Portal_Auth::begin_forced_password_change($e->identity), THEN park any
       destination state (invited client, redirect) - the call signs the
       portal out and clears portal session values - and redirect to the new
       route.
    2. Add #[Portal_Route('/login/new-password', methods: ['GET', 'POST'])]
       (reference: Portal_Login_Controller::new_password): signed in -> the
       destination; ?cancel=1 -> abandon_forced_password_change(); nothing
       pending -> /login; POST -> your length and confirmation rules, then
       Portal_Auth::complete_forced_password_change($password), catching
       Auth_Throttled_Exception and Forced_Password_Change_Exception
       (REASON_NOTHING_PENDING -> /login).
    3. Continue the returned portal user through the same ladder as a password
       sign-in (a second step if owed, else your one sign-in completion); one
       helper used by both paths (the template's __continue_sign_in()).
    4. Add the page (reference: portal_login_new_password.blade.php): a hidden
       read-only email field with autocomplete="username", new_password and
       new_password_confirmation with autocomplete="new-password", a Cancel
       link. If your portal auth bundle names files individually, add it.

VERIFICATION
    Flag a portal user and sign in: you land on the new page; the current
    password is refused; a new password reaches the portal, the flag is 0,
    and an action-log row records the change with cause forced_change.
