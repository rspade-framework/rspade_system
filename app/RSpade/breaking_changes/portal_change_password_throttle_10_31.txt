PORTAL CHANGE PASSWORD IS THROTTLED AND RECORDS A WRONG CURRENT PASSWORD
Date: 2026-10-31

IF YOU DO NOTHING: your portal settings screen's Change Password checks the current password with no limit and records nothing, so anybody holding a portal browser left signed in can guess the account's real password there as fast as they can send requests; and the screen shows no per-field error - every refusal, a wrong current password included, is a generic "Please correct the errors below." dialog.

SUMMARY
    Category 3: a template implementation to port.

    The framework's login throttle (rsx.sessions.login_throttle, 8 failures per
    60 seconds per address and per account) already guards every sign-in, the
    staff Change Password and the password confirmation. The template's portal
    Change Password now draws on the same budget: it checks the throttle before
    the current password, and counts a wrong one as a failed attempt. Its screen
    now shows the server's field messages.

WHAT YOU ALREADY HAVE
    Arrived automatically in system/, nothing to do:

    - Login_Throttle::require_not_throttled($account) and Auth_Throttled_Exception
      ("You're doing that too fast").
    - Portal_Login_History::record_failure($email, $status, $reason, $identity_id),
      which feeds the throttle.
    - The staff equivalent of this change shipped with the throttle itself
      (breaking_changes/login_throttle_rate_limit_10_29.txt, ACTION REQUIRED 1: the
      template's settings_password_security_controller.php change_password()).
      Port that too if you have not.

WHAT IS MISSING IN YOUR APPLICATION
    Your copy of the portal settings controller's change_password() and its
    screen's submit handler.

THE REFERENCE IMPLEMENTATION
    reference_app/portal/settings/portal_settings_controller.php, change_password():
        1. Every field rule first, answered together in one response_form_error().
        2. Login_Throttle::require_not_throttled($user->email), its
           Auth_Throttled_Exception caught and answered as
           response_form_error($e->getMessage()).
        3. A wrong current password recorded with
           Portal_Login_History::record_failure($user->email,
               Portal_Login_History::STATUS_FAILED_PASSWORD,
               'Wrong current password on Change Password', (int) $user->id)
           before the field error is returned.
    reference_app/portal/settings/Portal_Settings_Action.js, the password form's
    submit handler: clears the previous field errors, reads field messages from
    the Ajax error's `metadata` (every key but `_message`), and shows a refusal
    with no field - the throttle - in a dialog.

PORTING IT
    1. Copy the three steps above into your portal change_password(), with the
       use lines for Login_Throttle, Auth_Throttled_Exception and
       Portal_Login_History.
    2. In your screen's handler, read field errors from e.metadata, never
       e.errors (which an Ajax error does not have).
    3. A portal password form of your own that checks a current password does
       the same: throttle first, record a wrong answer.

VERIFICATION
    On a development box:
        php artisan rsx:debug /_portal/settings --portal --portal-user=<id> \
            --eval="const r = []; for (let i = 0; i < 9; i++) { try { await Portal_Settings_Controller.change_password({current_password: 'wrong-' + i, new_password: 'long-enough-1', confirm_password: 'long-enough-1'}); r.push('ok'); } catch (e) { r.push(e.message); } } return r.join(' | ');"
    The last answer is "You're doing that too fast". Clear it afterwards with
        php artisan tinker --execute="App\RSpade\Core\Auth\Login_Throttle::reset('<email>', '127.0.0.1');"
    A wrong current password on the screen shows "Current password is incorrect"
    under the field.
