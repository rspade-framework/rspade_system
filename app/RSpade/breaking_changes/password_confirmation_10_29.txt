PASSWORD CONFIRMATION BEFORE ADDING OR REMOVING A WAY INTO AN ACCOUNT
Date: 2026-10-29

IF YOU DO NOTHING: on your security settings screen, setting up an authenticator app, registering or removing a passkey, regenerating recovery codes, and connecting or disconnecting a federated account all fail with "Your password confirmation has timed out. Refresh the page and try again." - the framework endpoints behind those buttons now require a recent password confirmation your screen never asks for.

SUMMARY
    Category 3: a framework feature with a template implementation to port.

    A signed-in session is not proof the person at the keyboard owns the
    account. The actions that add or remove a way into an account now require
    the user to re-enter their password (or use one of their passkeys) within
    the last few minutes. The framework enforces it and ships the form; the
    dialog and the gating of each button are the application's.

WHAT YOU ALREADY HAVE
    Arrived automatically in system/, nothing to do:

    - Rsx_Password_Confirmation (PHP): require_confirmed() - the check, called
      first by the gated endpoints - plus is_confirmed(), options(),
      confirm_password(), confirm_passkey(), clear().
    - Rsx_Password_Confirmation_Controller: options, verify (Turnstile first),
      passkey_options, verify_passkey, clear. In every bundle.
    - Rsx_Password_Confirmation (JS): status() / is_confirmed() / verify() /
      verify_passkey() / clear().
    - <Password_Confirmation_Form>: the password with Turnstile, or a passkey;
      fires 'confirmed'; submit() resolves true/false. And <Password_Input>.
    - The gate on Rsx_Two_Factor_Controller and Rsx_Portal_Two_Factor_Controller
      (totp_begin, totp_confirm, passkey_register_begin, passkey_register_confirm,
      credential_remove, recovery_regenerate) and on Rsx_Sso_Controller and
      Rsx_Portal_Sso_Controller (link_begin, identity_unlink).
    - rsx.sessions.password_confirmation_minutes (5).

WHAT IS MISSING IN YOUR APPLICATION
    A dialog that asks for the confirmation, and the line in front of each
    gated button that opens it. Without them every one of those actions is
    refused for every user.

THE REFERENCE IMPLEMENTATION
    Under system/app/RSpade/resource/reference_app/:

    lib/password_confirmation/password_confirmation_modal.js
        Password_Confirmation_Modal.require(): true at once while confirmed,
        else Modal.show() hosting <Password_Confirmation_Form>, three tries,
        closing on a passkey. Uses this template's Modal; adapt to yours.
    app/frontend/settings/password_security/settings_password_security_action.js
        Every factor and connected-account button awaits require() first;
        on_stop() calls Rsx_Password_Confirmation.clear().
    app/frontend/settings/api_keys/
        settings_api_keys_controller.php create_key() calls
        Rsx_Password_Confirmation::require_confirmed(); add_api_key_modal.js
        asks before the form opens; the action clears in on_stop().
    portal/settings/Portal_Settings_Security.js (+ .jqhtml)
        The portal screen: remove / disconnect / regenerate ask on click;
        <Passkey_Register>, the authenticator app and <Sso_Buttons
        $intent="link"> are shown only after "Add a sign-in method" asked,
        because those components call their endpoints themselves.
    tests/playwright/password_confirmation_modal.js
        The dialog's behaviour.

PORTING IT
    Your screens decide where the dialog lives and how it looks.

       a. Copy lib/password_confirmation/password_confirmation_modal.js into
          rsx/lib/ (or write your own dialog around <Password_Confirmation_Form>).

       b. In front of every button that reaches a gated endpoint:
              if (!await this.alive(Password_Confirmation_Modal.require())) return;
          A component that calls a gated endpoint itself (<Passkey_Register>,
          <Totp_Enrollment>, <Sso_Buttons $intent="link">) is mounted only
          after require() answers true.

       c. On each such screen:
              on_stop() { Rsx_Password_Confirmation.clear(); }

       d. Optionally gate sensitive endpoints of your own - minting an API key
          is the template's - with Rsx_Password_Confirmation::require_confirmed()
          as their first statement, and the dialog in front of their buttons.

       e. Tests of yours that call a gated endpoint for some other purpose set
          Rsx_Password_Confirmation::$force_confirmed_for_tests = true in
          setup() and null in teardown().

VERIFICATION
    On your security screen, Remove (or Set Up) asks for the password, a wrong
    password is refused in the dialog, the right one completes the action, and a
    second action within the next few minutes does not ask again. Leaving the
    page and coming back asks again. rsx:man password_confirmation.
