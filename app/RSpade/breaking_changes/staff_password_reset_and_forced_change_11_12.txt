STAFF PASSWORD RESET: "FORGOT YOUR PASSWORD?", ADMINISTRATOR RESET PASSWORD, AND THE FORCED CHANGE AT SIGN-IN
Date: 2026-11-12

IF YOU DO NOTHING: a staff user flagged password_reset_required (by rsx:users:force_password_reset or rsx:users:password:set --require-reset) still meets your login form's error and cannot sign in until an operator runs rsx:users:password:set, your sign-in page offers no "Forgot your password?", and your User Management has no way for an administrator to set a temporary password - the framework halves below exist, but nothing in your application calls them.

SUMMARY
    Category 3. A staff password can now be reset three ways, and a password that
    must be replaced is chosen at sign-in rather than through an operator:

      - the FRAMEWORK gained the forced password change at sign-in (both realms),
        Login_User_Model::set_password(), a fix to require_password_reset() on an
        identity that is already flagged, and rsx:users:password:set
        --require-reset;
      - the REFERENCE APPLICATION gained "Forgot your password?" for staff (an
        emailed single-use link), an administrator's Reset Password in User
        Management (a temporary password the user must replace), and the
        "Choose a new password" step on its staff sign-in.

    Your /rsx/ receives none of the application half. Port what you want; the
    framework half needs nothing from you.

WHAT YOU ALREADY HAVE
    - RsxAuth::begin_forced_password_change(Login_User_Model $identity),
      forced_password_change_pending(): ?array {email},
      complete_forced_password_change(string $new): Login_User_Model and
      abandon_forced_password_change(); Portal_Auth has the same four for a
      Portal_User_Model. begin signs the realm out and parks the identity;
      complete refuses an empty password and the CURRENT one
      (Forced_Password_Change_Exception, reason() nothing_pending / empty /
      unchanged), asks the sign-in throttle first (Auth_Throttled_Exception),
      saves through the model and answers the identity STILL NOT SIGNED IN.
      Your login function then runs the second factor, then signs in.
      rsx:man session, FORCED PASSWORD CHANGE AT SIGN-IN.
    - Login_User_Model::set_password($plain) (hashes; does not save) - the
      staff twin of Portal_User_Model::set_password().
    - require_password_reset() now holds through a save that also sets a new
      password EVEN WHEN THE IDENTITY WAS ALREADY FLAGGED. Before, assigning
      1 over 1 was not "dirty" and the password-change hook cleared the flag:
      a temporary password given to an already-flagged user silently un-flagged
      them. If your code issued temporary passwords that way, it now does what
      it said.
    - rsx:users:password:set --require-reset sets a temporary password.
    - Login_User_Model / Portal_User_Model (likely-overridden): an override
      extends the base and inherits all of the above. Only an override that
      REDECLARES require_password_reset() or booted()'s password hooks must
      chain into the base (parent::) or restate the new instance property
      $_password_reset_asserted.

WHAT IS MISSING IN YOUR APPLICATION
    - A staff user given a temporary password, or flagged by an operator, cannot
      get past your login form by themselves: there is no page to choose the new
      password on.
    - A staff user who forgot their password has no way to reset it without an
      operator at a shell.
    - An administrator has no screen to set a user's temporary password.

THE REFERENCE IMPLEMENTATION AND PORTING IT
    Every path below is under system/app/RSpade/resource/reference_app/ (your
    disk, release-current). Your navigation, permission model and design system
    decide where each piece lands; the rules each paragraph names are the part
    to keep.

    1. THE FORCED CHANGE AT SIGN-IN (recommended for every application with a
       staff password form). Where your login function catches
       Auth_Password_Reset_Required_Exception, park the identity and send the
       visitor to a "Choose a new password" page instead of showing an error:

           // before
           } catch (Auth_Password_Reset_Required_Exception $e) {
               $error = $e->getMessage() . ' Contact your administrator to have it reset.';
           }

           // after
           } catch (Auth_Password_Reset_Required_Exception $e) {
               RsxAuth::begin_forced_password_change($e->identity);
               return redirect(Rsx::Route('Login_Controller::new_password'));
           }

       Add the page: a public GET+POST route that redirects to /login when
       forced_password_change_pending() is null, checks YOUR password rule and a
       confirmation, calls complete_forced_password_change(), and then
       continues exactly as after a successful verify_credentials() - the
       second-factor challenge when the identity holds one, otherwise your
       completion function (which calls RsxAuth::login()). Put the second
       factor AFTER the new password, never skip it. Its fields: a hidden
       read-only autocomplete="username" field carrying the pending address,
       then new_password / new_password_confirmation (autocomplete
       "new-password"). Reference:
           system/app/RSpade/resource/reference_app/app/login/login_controller.php
               (index(), new_password(), __continue_sign_in())
           system/app/RSpade/resource/reference_app/app/login/login_new_password.blade.php

    2. "FORGOT YOUR PASSWORD?" FOR STAFF. A token table, a model, a
       controller with two pages and an invalid-link page, a SECURITY email,
       a link on the login page, and two config keys:
           migration   rsx/resource/migrations/2026_11_12_050112_create_login_user_password_resets_table.php
           trait       rsx/lib/password_reset/password_reset_token.php
           model       rsx/models/login_user_password_reset_model.php
           controller  rsx/app/login/password_reset/ (controller + three blades)
           email       rsx/emails/password_reset_email.php (+ .blade.php)
           login page  rsx/app/login/login_index.blade.php ("Forgot your password?")
           config      rsx/resource/config/rsx.php: rsx.auth.password_min_length,
                       rsx.auth.password_reset_expiry_hours; rsx.login_notices
                       'password_reset'
       Run
       php artisan make:migration:safe <name> --path=rsx/resource/migrations and
       copy the SQL. The rules: the table stores only SHA-256 of the link's
       secret; one live link per identity; single use by an atomic claim();
       completing it ends the identity's other open links; the request page
       answers the same sentence for every address; completing signs nobody
       in and sends the visitor to /login.

    3. THE PORTAL'S RESET TOKENS (if you port item 2's trait). The reference
       Portal_Password_Reset_Model now uses the same trait, so its table stores
       token_hash instead of token: copy
           rsx/resource/migrations/2026_11_12_050113_hash_portal_password_reset_tokens.php
       (it hashes existing rows in place, so links already sent keep working)
       together with the model and the two-line change in
       Portal_Password_Reset_Controller (find_by_secret(), invalidate_open_for()).
       If you keep your own portal model, nothing changes for you.

    4. ADMINISTRATOR "RESET PASSWORD" IN USER MANAGEMENT. Endpoints
       set_user_password and get_user_for_password_reset, the refusal helper,
       can_reset_password on get_user, the dialog, and the button:
           rsx/app/frontend/settings/user_management/settings_user_management_controller.php
           rsx/app/frontend/settings/user_management/reset_password/
           rsx/app/frontend/settings/user_management/view/ (button + handler)
       It sets the password and require_password_reset() in ONE save, ends the
       user's open reset links, needs a recent password confirmation, and is
       refused on the caller's own account, on a superior, on a user who has not
       signed up, and on an identity that belongs to another site too. That
       last refusal is BY DESIGN: the password is one credential across every
       site, and one site's administrator has no authority over the others;
       the user resets it themselves, or an operator does
       (rsx:users:password:set --require-reset). A single-site application
       never meets it; one that wants another path adds its own endpoint with
       its own authority rule rather than loosening the refusal.

    5. ONE PASSWORD RULE (optional). The reference app reads
       rsx.auth.password_min_length on every staff form that chooses a password
       (accept invite and Password & Security too), replacing the literal 8 and
       Frontend_Settings_Password_Security_Controller::PASSWORD_MIN_LENGTH.

VERIFICATION
    - rsx:users:password:set --user=<a test user> --password=<temp> --require-reset,
      then sign in with <temp>: "Choose a new password" appears, choosing one
      signs you in (or asks your second factor first), and the flag is 0.
    - /password/reset with that user's address queues one Password_Reset_Email
      (php artisan rsx:mail:queue); its link sets a password once.
    - User Management > a user > Reset Password: the user is signed out and
      meets "Choose a new password" at their next sign-in.
