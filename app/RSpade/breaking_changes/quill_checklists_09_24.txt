QUILL 2 CHECKLISTS SURVIVE safe_html(); THE READ VIEW THAT DRAWS THEM IS A TEMPLATE PORT
Date: 2026-09-24

IF YOU DO NOTHING: a checklist authored in a rich-text field now keeps its ticks
    through save and reload, but your read view (your copy of
    Rich_Text_Display) shows each checklist item as a plain bullet, so a
    reader cannot see which items are ticked.

SUMMARY
    Quill 2 stores a checklist item's state as li[data-list="checked"] or
    li[data-list="unchecked"]. Both safe_html() implementations now keep that
    attribute - on an li only, and only with Quill's four values (checked,
    unchecked, ordered, bullet). Before, it was stripped, and every checklist
    became a plain list on save. Nothing else in the allow-list changed.

    Contract: php artisan rsx:man safe_html (CHECKLISTS)

THE REFERENCE IMPLEMENTATION
    system/app/RSpade/resource/reference_app/theme/components/view/
    rich_text_display/rich_text_display.scss
        The block commented "A checklist item": li[data-list="checked"] and
        li[data-list="unchecked"] lose their list marker and gain a drawn box
        (::before) and, when checked, a tick (::after), in theme tokens.

PORTING IT
    Copy that block into your Rich_Text_Display stylesheet (or whatever
    component prints your rich-text type). To let authors make checklists, add
    { list: 'check' } to a Wysiwyg_Input toolbar - the shipped toolbar does not
    offer it.

VERIFICATION
    Author a checklist, tick an item, save, reload the edit page: the tick is
    still there. On the read view the ticked item shows a ticked box.
