DARK MODE IS NOW A FRAMEWORK FEATURE
Date: 2026-08-27

SUMMARY
    RSpade now owns the theme preference: a per-identity light/dark/auto setting
    stored on login_users, resolved server-side, and rendered onto <body> before
    the page loads.

    This affects you ONLY if your app already implements a dark mode of its own.
    An app with no dark mode gets a working one by declaring two config keys and
    styling against one class - nothing to migrate.

    An app that already has one now has TWO implementations of the same idea, and
    they will fight: yours applies a class from JavaScript, the framework's
    applies its own class from the server. Pick the framework's and delete yours.

THE CHANGE
    New in /system/:

        login_users.dark_mode           BIGINT enum, default 2 (auto)
        Rsx_Dark_Mode                   resolve / read / write the preference
        Rsx_Dark_Mode_Controller        get_settings, set_dark_mode (staff realm)
        Rsx_Dark_Mode.js                resolves AUTO in the browser, follows the OS
        window.rsxapp.theme             mode, is_dark, dark_class, the attribute sets

    <body> now carries, on every page:

        rsx-theme-light|dark|auto   the MODE that was chosen
        rsx-dark                    dark is ACTIVE right now
        plus any attributes the app declares (see ACTION REQUIRED)

    THE MODEL IS SERVER-FIRST. An explicit light or dark preference is resolved in
    PHP and painted in the first bytes of HTML, so there is no flash to fix. AUTO
    is the exception and cannot be resolved server-side - prefers-color-scheme
    exists only in the browser - so the framework emits the mode and resolves it
    at boot, keeping up with the OS live.

THE FIX
    Nothing to copy. The column, the service, the controller, the JS and the body
    rendering all arrive with the submodule. The migration runs on your next
    `php artisan migrate`.

ACTION REQUIRED

    1. DECLARE YOUR THEME VOCABULARY (every app, one-time)

       The framework renders no UI-toolkit attribute of its own - it ships no
       toolkit and no colours. If your CSS keys off an attribute, declare it in
       rsx/resource/config/rsx.php:

           'theme' => [
               'dark_mode' => [
                   'attributes' => [
                       'dark'  => ['data-bs-theme' => 'dark'],
                       'light' => ['data-bs-theme' => 'light'],
                   ],
               ],
           ],

       Use whatever attribute your CSS actually reads. An app that themes purely
       off the rsx-dark class declares nothing at all.

       Declaring it here rather than setting it in a layout is what gets it onto
       <body> BEFORE first paint. Setting it from JavaScript reintroduces the
       flash this feature exists to remove.

    2. IF YOU HAVE YOUR OWN DARK MODE, MIGRATE IT

       a) Replace your body class with the framework's.

          Search your SCSS for your own dark selector and repoint it:

              body._dark_mode        ->   body.rsx-dark
              body.dark, .theme-dark ->   body.rsx-dark

          The framework class is configurable if a mass rename is impractical -
          set config('rsx.theme.dark_mode.dark_class') to the name your CSS
          already uses and skip the rename entirely. Only the DARK class is
          yours to name; the rsx-theme-* mode classes are fixed.

       b) Delete your own preference storage.

          If you kept the mode in a preferences table, a user column or browser
          storage, that is now a second source of truth. Move any existing values
          across once, then stop reading yours:

              foreach (Login_User_Model::query()->result_set() as $login_user) {
                  $old = /* your lookup for this identity */;
                  if ($old === null) { continue; }
                  $login_user->dark_mode = $old;   // 0 light / 1 dark / 2 auto
                  $login_user->save();
              }

          Note the framework preference is per IDENTITY (login_users), not per
          user-per-site. If yours was site-scoped, one value has to win - the
          most recently updated is the usual choice.

       c) Delete your JavaScript that applies the class.

          A layout hook that reads your flag and calls toggleClass is now doing
          the framework's job a frame too late, and under an explicit preference
          it is fighting markup the server already got right. Remove it. The only
          case still needing JavaScript is AUTO, which Rsx_Dark_Mode.js handles.

       d) Point your settings screen at the framework controller.

              const result = await Rsx_Dark_Mode_Controller.set_dark_mode({
                  dark_mode: Rsx_Dark_Mode.MODE_DARK,
              });

          Delete your own save endpoint. A pass-through in your app would be a
          second way to do one thing.

       e) Replace a post-save reload with Spa.disable().

          If you reloaded the window after saving, you no longer need to:

              if (result.changed) {
                  Spa.disable();
                  Flash_Alert.success('Theme saved. The app will switch over when you navigate away.');
              }

          The SPA keeps working and the NEXT navigation becomes a full page load,
          which re-renders <body> in the new theme. A user still editing other
          settings is not thrown out of the page to recolour it.

    3. CHECK YOUR MODE VOCABULARY

       The framework's modes are 0 light / 1 dark / 2 auto, as
       Login_User_Model::DARK_MODE_*. If yours used different values, strings, or
       only two states, map them at the point of migration (2b) - and note that
       auto is the DEFAULT, so an app that previously defaulted to light will find
       users following their OS unless you set
       config('rsx.theme.dark_mode.default') to 0.

VERIFICATION
    1. Sign in and set the theme to Dark, then navigate to any page and View
       Source. The <body> tag itself must carry rsx-dark - if you only see it in
       the DOM inspector and not in the source, something is still applying it
       from JavaScript.

    2. Set the theme to Auto and switch your OS between light and dark with the
       app open. The page follows without a reload.

    3. Save a theme change and DO NOT reload. The current page keeps the old
       theme; the next link you click loads the new one.

    4. Confirm one source of truth:

           grep -rn "_dark_mode\|theme-dark\|darkMode" rsx/ --include=*.js --include=*.scss

       Anything still matching your old vocabulary is a leftover.

    Full reference: php artisan rsx:man dark_mode
